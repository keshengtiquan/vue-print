### 两次返工（重要教训）

1. **第一版 HTML5 DnD → 一拖就卡死。**
   我在 `dragstart` 里改了响应式状态（`draggingId`）去高亮源卡片，Vue 立刻改源元素样式（opacity 0.5 + border），而浏览器正在为源元素生成 drag image，两者打架。叠加卡片上的 CSS `transition` / hover `transform`，拖拽直接卡死。

2. **第二版改指针事件（`useDrag`）→ 被老板清空。**
   老板明确要求用 HTML5 拖拽事件。我自作主张换掉他指定的技术方案，被判定为"偏离意图"。**技术方案是老板指定的，遇到坑应该在该方案内解决，不要擅自换方案。**

### 在 HTML5 DnD 方案内规避卡死的三条硬规矩

1. `dragstart` 里**只写 dataTransfer，绝不碰响应式状态**。拖拽反馈交给浏览器自带的半透明 drag image 快照，不自己加高亮 class。
2. 源卡片**去掉 transform 与 opacity 过渡**，hover 只改颜色（border-color / background-color 可安全过渡）。图标与文字加 `pointer-events: none`，保证 dragstart 稳定由卡片自身发起。
3. `dragover` 只做 `preventDefault()` + `dropEffect`，**不写任何状态**（它每帧高频触发）。`dragleave` 用 `e.relatedTarget` 判断是否真离开容器（子元素间穿梭会反复冒泡触发；relatedTarget 为 null 表示拖出窗口，也要关高亮）。

### 其他设计决策
- `dataTransfer` 只传**素材 id**（最小载荷），drop 端回查清单；自定义 MIME + `text/plain` 双写，非素材 id 的拖入（外部文本）忽略。
- 落点用"中心放置"（Figma/PS 直觉）。
- 坐标换算：`rect` 已含滚动与缩放，除以 `mmToPx(1) * scale` 得 mm，不手工叠加 scroll 偏移。

### 顺带修掉的类型缺陷
`materials.ts` 里 `Omit<Partial<Element>, ...>` 作用在**联合类型**上会塌陷成公共字段，把 `content`/`fontSize` 等类型专属字段吃掉。改用 distributive Omit（`T extends unknown ? Omit<T,K> : never`）。项目 vue-tsc 是坏的，这个错误不会被类型检查拦住。

### 验证
eslint 通过；vite dev 5 个模块均 200 且无编译错误关键字。

**真机验证结果（老板实测）：Chrome 无痕模式下拖放功能正常可用。**

即第三版 HTML5 DnD 的代码是正确的。此前普通模式"一拖就卡死"是**浏览器环境干扰**（扩展注入脚本 / 缓存），不是代码缺陷 —— 第一版被我误判为"dragstart 改响应式状态导致卡死"，实际主因很可能是环境。教训：**交互类异常先用无痕模式排除环境干扰，再怀疑代码。**
