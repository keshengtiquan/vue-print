# 数据绑定（API 接口链路）

> 计划书：`docs/data-binding-design.md`（§6 绑定层、§11 实现进度）。**改数据层 / 渲染前读它。**
> 本文件收"会返工的约定"，不是教程。

## 三层模型

```
数据源（连接信息） → 数据集（查询声明 + 字段快照） → 绑定（元素 / 表格引用数据集）
```

- 接口（`type: "http"`）与 SQL（`type: "sql"`）**不是两条平行路线**，是同一个 `type` 字段。
  差别只在"谁执行"：浏览器能自己发 HTTP；SQL 数据集**明确拒绝**并提示"必须由宿主执行"。
- 纯前端产品**一律不做 SQL 直连**（ActiveReportsJS / Stimulsoft / hiprint 都如此）—— 竞品调研的结论。

## 铁律（违反会返工）

### 1. 绑定的唯一来源是元素自己的 `binding.dataSetId`

**没有"主数据集 / 默认数据集"这个概念**（老板 2026-09-20 拍板整体移除，计划书 §11.9）。

- 绑谁 = 用户往它里面拖了哪份数据的字段。
- `FieldNode` 的拖拽载荷是 `{ dataSetId, field }` —— **接收端两个字段都要用**，只取 `field` 就丢了绑定。
- 没绑定的元素**按静态内容渲染，绝不猜测性兜底**。兜底猜错会让画布显示另一份数据、且毫无提示。
- `selectedDataSetId` 只是**面板上下文**（字段树显示哪份字段），不参与画布渲染。

### 2. 设计态画布不渲染字段值

老板 2026-09-20 纠正过一次实现偏离（计划书 §11.10）。内容里写 `{品名}`，画布上就显示 `{品名}`，**一个字符都不替换**。
出发点是两条早就写好的约束：表格文档 §1.5 约束 2 + 计划书 §6.7。

- **看门狗**：`grep -rn "renderTemplate" src/components/design/designPanel/` **必须零命中**。
- `renderTemplate` 与 `designContext` **当前零调用点**（面板「取数预览」也已移除，2026-09-20 晚），
  它们只服务将来的预览 / 导出 / 打印 —— 是**接缝，不是遗漏**。
- **不给占位符加任何视觉标记**（底色 / 虚线框 / 加粗）—— 会改字宽、破坏排版测量。
- 表格**不做任何扩展**（2026-09-20 拆掉了明细行机制，见本档末尾）：画布只渲染模板网格，"哪一行会重复 N 遍"是导出 / 套打的语义，不是画布的事。
- ⚠️ 图片元素含占位符时**绝不能把 `{字段}` 当 `src` 交给浏览器**（会被当相对路径发 404 + 裂图），
  要返回空串走"显示占位符文本"分支。

### 3. 插入的占位符一律带数据集标识

形态 `{数据集.字段}`（如 `{数据集1.品名}`）。

- **唯一构造点**：`useDataBinding.fieldToken(field, dataSetId)`。别在任何地方手拼 `{字段}`。
  自查：`grep -rn '`{\${' src` 应只命中它一行。
- 前缀用 `dataSet.name`（面板上叫「标识符（占位符前缀）」）。它的校验 `isValidDataSetName`
  已排除空格 / 点号 / 花括号 / `$`。**点号尤其关键**：`splitTokenKey` 按**第一个点**切，名字带点会切错。
- `label` 是显示名（允许空格、允许重名），**不能当前缀**。
- 旧的无前缀 `{字段}` 仍照常取值，**不要做自动改写**（那是替用户改内容）。

## 取值语义（`context.ts`）

- `{字段}` / `{数据集.字段}` / `{address.city}` 三种写法靠"前缀是不是一级字段名"区分：
  前缀 == 本数据集名 ⇒ 正常取字段；前缀是一级字段名 ⇒ 当对象路径取；都不是 ⇒ 返回缺值（显示原样占位符）。
- **`{字段}` 与 `${参数}` 是两套东西**：前者是"要填进来的数据"，后者是"要送出去的查询条件"。
  混了轻则查不到数据、重则是一次注入。
- 缺值判定只看 `null` / `undefined`。空字符串 `""` 是"有值且为空"，渲染成空。

## 界面约定

- 画布 = **排版视图**（显示占位符）。**当前全应用没有任何地方显示字段值**（2026-09-20 晚定稿）。
- 绑定面板只有两块：**数据集下拉** + **插入字段**（仅文本 / 图片）。
  表格的「数据」分组**只剩「数据集」一个下拉** —— 明细模板行 / 列映射 / 取数预览全部移除（见下）。
  「表头行数」输入框更早已移除（计划书 §11.14）。

## 表格：数据侧能力整体不做（2026-09-20 晚定稿，**这是最新结论**）

**一句话：表格只通过 `BaseElement.binding.dataSetId` 与数据沾边。** 它知道"我这张表用哪个数据集"，
单元格里可以有 `{数据集.字段}` 文本，但**没有任何取数行为** —— 不展开行、不填值、不显示值。

- **保留的写入路径**：往单元格拖字段（`appendFieldToCell`）仍然有效 —— 它只是"把 `{数据集.字段}`
  写进这一格"，与数据扩展无关；表格的绑定仍由它顺手完成。
- **`rowRoles` / `headerRows` / `detailRowIndex` / `columnFields` 四个字段今天被反复增删，现在全部不存在**；
  `data/tableRender.ts` **已整个删除**。增删史看计划书 **§11.12 / §11.14 / §11.15 / §11.16**，
  **别再自己推**，更别照着 §11.15 实现一遍。
- **两条教训（比任何字段都值钱）**：
  1. 一个功能如果**改了画布上看不见、只有预览里看得见**，它大概率不属于设计态 ——
     设计态要回答的是排版（几行、多高、会不会撑出纸），**不依赖样本数据**。本轮返工的全部原因就是这条。
  2. "只存不消费 = 死数据 = 删"的适用范围要**收窄**：它针对的是**会让用户误以为生效的面板声明**
     （调了没反应的下拉 / 输入框）。**内部模块**暂时没有消费方**不算死**
     （如 `context.ts` / `renderTemplate` / `designContext`，它们是渲染态的接缝）。
     判定标准：**它会不会让用户以为某件事生效了？** 会 → 删；只是暂时没人调 → 留。
- **重建导出 / 打印时**：按计划书 §11.16 的"重建清单"来（先有声明、再有渲染、面板与导出共用一份纯函数），
  并且**第一个要回答的问题是"画布要不要看见"**。
- 套打行数控制三件套（`detailRowsPerPage` / `padEmptyRows` / `summaryOnLastPageOnly`）仍未做。
- **仍然只存不消费、老板尚未表态的**：`TableElement.allowBreakAcrossPages`（允许跨页断行）。
- **`TableElement.vue` 里"为什么表格用真 `<table>` 而不是 div 网格"那段注释必须留着**
  （`<thead>` 原生分页是 div 网格拿不到的能力）。它现在的措辞是"重建时先把声明加回来"。
