## 文本元素内联编辑（右键「编辑文本」+ 双击）

老板拍板：textarea 方案、双击进入、失焦即退出、Esc 只提交不回滚。

- `store/modules/design.ts`：新增 `editingId` + `startEditing(id)` / `stopEditing()`。清理集中在 store：`selectElement(id)` 里 `id !== editingId` 就清、`removeElement` 里清、`updateElement` 里发现 `locked` 就清（这样所有加锁路径都自动满足，不用各处记得清）。
- `elements/TextElement.vue`：编辑态用 `<textarea>` 覆盖，复用 `textStyle` 保证与渲染态同字体同字号；`editorStyle` 额外补 `width:100%`、横排走 autosize。
  - **本地 `draft` ref 作 textarea 的 `:value`**，`@input` 里同步写 store。draft 恒等于 DOM 值 → Vue patch 必跳过 → 中文输入法合成期间不会被外部写入打断。
  - **autosize 的坑**：`scrollHeight` 会被"当前过大的高度"顶住，所以要先临时塌成 `auto` 再量；量完必须还原成**原值**，不能清空 —— 高度没变化时 Vue 不会重新落样式，清空会让框永久塌成一行。
  - 上层 `select-none` 会继承下来，textarea 必须自己加 `select-text`，否则鼠标选不中文字。
  - `@pointerdown.stop` 必须有，否则在文字里拖选会变成拖整个元素。
  - `onBlur` 里先判断 `isEditing` 再 stop：元素被移除时浏览器会补一次 blur，不判断会把用户随后开始的新编辑会话掐掉。
  - Esc 里判断 `e.isComposing`：组字中的 Esc 属于输入法，不该关编辑器。
- `elements/ElementWrapper.vue`：`editing` 时隐藏 8 个手柄 + 旋转柄；`onPointerDown` 在编辑态**提前 return 且不 preventDefault**（拦了默认行为 textarea 就不会失焦，编辑态会关不掉）；新增 `@dblclick` 进编辑（手柄上挂 `@dblclick.stop`，双击手柄不该进编辑态）。
- `elements/ElementContextMenu.vue`：命令落到 `store.startEditing`；锁定时该项**灰掉**、已在编辑时该项隐藏；`ContextMenuContent` 挂 `@close-auto-focus` 并在本次要进编辑时 `preventDefault()` —— reka 关闭菜单会把焦点回填给 trigger（不可聚焦的 div → 掉到 body），不回拦就会顶掉刚聚焦的 textarea。
- `designPanel/index.vue`：`deselect` 从直接赋 `selectedId = null` 改成走 `selectElement(null)`，否则点空白只清选中、不清编辑态。
- **没改** `ElementProperties.vue`（方案里原本要给"内容"字段加 `:disabled="locked || editing"`）：禁用的控件点不着，画布 textarea 就不会失焦，用户会觉得面板那片是死的、要点两次。既然定了"失焦即退出"，两条编辑路径天然互斥，不需要禁用。

验证：eslint + curl 转换产物 + 回查 `select-text` 等类是否被 Tailwind 生成。

## reka-ui 焦点回填（可复用）

`ContextMenuContent`（以及其它 Content 类）关闭时走 FocusScope 的 `onUnmountAutoFocus` → `emits("closeAutoFocus", e)`，然后按 `defaultPrevented` 决定要不要把焦点还给 trigger。要阻止就用 `@close-auto-focus` + `preventDefault()`，这是**确定有效**的时机（emits 同步，自己的处理函数一定先跑完）。比"在 nextTick 里延迟聚焦"可靠。
