## 「主数据集」概念澄清（老板提问："是只能有一个数据集吗？"）

- **答案：不是。** `dataSets` 是数组，元素各自通过 `binding.dataSetId` 指向任意一个。
- 「主数据集」的真实身份 = **"元素没显式绑定时的兜底默认值"**，不是"唯一的数据集"。全项目只有 **3 个消费点**：
  - `design/data/useDataBinding.ts` `effectiveDataSet()` —— `dataSetById(el.binding?.dataSetId) ?? primaryDataSet`
  - `setting/element/BindingSection.vue` —— 下拉里把空值显示成"主数据集"
  - `data/DataPanel.vue` —— 数据集列表上的小圆点
- 它解决的问题：单据头的多个单值元素（客户名/单号/日期）通常来自同一份数据，没有默认值的话每拖一个元素都要手选一次数据集。
- 删掉默认数据集时 `removeDataSet` 会自动接替到 `dataSets[0]`；没显式设过时 `primaryDataSet` 也回落 `dataSets[0]`。
- **命名歧义**：叫"主"容易被理解成"唯一/从属"。老板正是被这点绊住 → 建议改名「**默认数据集**」。

### ⚠️ 发现一个真缺陷（未修，待老板拍板）

`effectiveDataSet()` 用 `??` 串联，**无法区分"没绑"和"绑了但数据集不存在"**：
显式绑了 `ds-x` 但该 id 已消失（模板 JSON 被手工编辑、未来做跨模板复制粘贴等）→ 静默回落到默认数据集，用户以为在用 A，实际渲染的是 B 的数据，且无任何提示。
`removeDataSet` 会清理绑定，所以正常删除路径安全。修法是一行 —— 显式绑定时只认真实存在的那个，找不到就返回 `undefined`（渲染成"绑定失效"）：
```ts
const id = el.binding?.dataSetId;
if (id) return binding.dataSetById(id);
return binding.primaryDataSet;
```

## 接通列映射：恢复「明细模板行」+ 整表取数预览（2026-09-20 下午）

**经过两轮问答**：老板先问"列映射是干嘛的" → 复核出它是**只写不读的死声明**，我建议删；
**老板选择的是"接通成真正的取数路径"**。再问"数据行在哪显示" → 老板选**面板整表预览**
（画布保持只显示占位符，§11.10 继续有效）。

**关键论证（这次讲清了一个绕不过去的前提）**：一个数据格拿到值，需要**两个映射同时成立** ——
「列 → 哪个字段」（有）**＋「行 → 哪条记录」（根本不存在）**。
§11.12 删掉明细行后 `rowViews` 就是 `gridCells(el)` 的直接映射，所以"整列取数"没有落点：
3 行 × 4 列的表、第 2 列绑 `单价`，三个格子取的是同一条记录的同一个值。
**结论：列映射不可能单独接通，必须和"行 → 记录"一起成立** —— 这也是为什么要把上一轮删掉的东西加回来一部分。

**设计（最小必要集）**：

- **只恢复 `detailRowIndex?`** 一个字段（明细模板行行号）。`undefined` = **整表静态**，行为与之前**完全一致**。
  **刻意不恢复 `rowRoles`**（确认过的死数据）：表头 / 明细 / 尾行用"与明细行的相对位置"表达就够。
- **取值优先级（两个入口、一条路径）**，唯一实现在**新增的 `data/tableRender.ts`**（纯函数、与 DOM 无关）：
  ① 格里有内容（含占位符）→ 渲染它（**静态内容优先**，写"合计"不会被列映射覆盖）
  ② 格是空的 且该列有 `columnFields[c]` → 取该字段值（**列映射的落点**）
  ③ 都没有 → 空
  ⚠️ 这与 §6.4"禁止第二条隐式写入路径"**不冲突**：列映射是**取值期兜底**，**绝不回写单元格内容**。
- **可见性**：画布不变；面板新增**整表取数预览**，与将来的导出 / 打印**共用 `renderTableRows()`**
  —— 展开逻辑只有一份，所以"预览里看着对、打出来不对"从结构上不可能发生。

**顺带修掉两个静默 bug**（同一个病根：声明与实际脱节）：

1. `syncColumnFields` 是**无人调用的死代码** → 删掉第 1 列后第 2 列下拉显示的是原第 2 列的字段（整体错位一位）。
   修法：把同步挪进 `insertCol` / `removeCol` **内部**，函数删除。
   **教训：结构变更的维护必须和结构变更写在同一个函数里；跨层调用只会再断一次。**
2. `detailRowIndex` 没有行号维护 → 插 / 删行后指向错行，或指向已被删掉的行。
   修法：`insertRow` 插在它前面则 +1；`removeRow` 删掉它则**清掉声明**（不钳到相邻行 —— 钳过去等于悄悄换了一行）。

**验证**：vite(5214) + curl **9 模块全 200**；`eslint` 改动范围 **0 problem**；
`syncColumnFields` / `headerRows` 在 `src/` 只剩说明性注释；`detailRowIndex` 有真实消费者。

**文档同步**：计划书新增 **§11.15**；§11.4 第 4 条"列映射的自动填值（未做）"改写为已落地；
§6.4 的 `columnFields` 定位与 §7.2 交互链路第 3 条同步改成"取值期兜底、不往回写格子"。
