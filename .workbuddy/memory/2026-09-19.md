## 合并格双击后选区背景只盖一角（老板报）

**现象**：两个单元格合并后双击进文本编辑，蓝色**边框**盖住整个合并区（正确），但蓝色**背景**只盖住合并区的一角。老板明确说"单击选中是对的，我说的是双击选中背景色不对" —— 这句话把事情从渲染层引开了。

**根因**：两层高亮的"扩张责任"不一致。
- `selectionRect`（`bg-primary/10` 蓝底）**直接读 `store.cellRange`**，存什么画什么，不扩张；
- `activeRect`（蓝框）内部过了 `rangeOfPoint(el, activeCell)`，自己扩过。

而 `startCellEditing(r, c)` 里把选区写成 1×1：`this.cellRange = { r1: r, c1: c, r2: r, c2: c }`。
于是蓝底只覆盖合并区的宿主格一个网格坐标 → 只有一格宽；蓝框因为自己扩过 → 整格。
**"框完整、底残缺"这个不对称形状，就是两条路径扩张责任不一致直接长出来的。**

这条不变量别处都遵守（点选走 `rangeOfPoint`、框选走 `normalizeRange` + `expandRange`），**只有双击这条绕过了**。

**改法**（`src/store/modules/design.ts`，只改赋值）：
```
const range = clampRange(expandRange(el, rangeOfPoint(el, r, c)), el);
this.cellRange = range;
this.activeCell = { r: range.r1, c: range.c1 };
this.cellEditing = { r: range.r1, c: range.c1 };
```
- 顺带把坐标归一到合并区**宿主格**（左上角）：`cellEditing` 是给渲染层比对 td 坐标用的，而 td 只画在宿主格上。
- `moveActiveCell` 是同一类违反（1×1 交给只夹取不扩张的 `setCellRange`），虽无调用方（键盘导航未做）也一并补上，否则留个已知缺口。
- 顺带确认 `expandRange` 对"被覆盖坐标"也对：`buildTableMap` 把每个被覆盖坐标都指回**宿主格 ref**，所以从小格子起点能迭代出整个合并区。

**验证**（临时脚本跑真 `model.ts`，Node 22，跑完已删）：22 条断言全绿 ——
120mm×4 列表中合并 (0,0)-(0,1) 后**旧行为蓝底宽 30mm（正好一半，复现现象）**、新行为 60mm 且与 `activeRect` 几何一致；
从被覆盖点 (0,1) 双击时旧行为蓝底还**偏移到 30mm 处**（跑到合并区中段）；
纵向合并 / 2×2 合并 / 贴右下角合并区都不越界；
**回归**：无合并时 12 个普通格新旧行为完全一致。`curl` 200、`eslint` 0 错误。

**未做浏览器验证**，需老板双击合并格确认蓝底铺满整格。

## 线宽的两个默认值不对（老板报，v12）

老板报："表格线宽默认怎么是 0，应该为 1"、"单元格的边框默认是 0.98"，并自己诊断"是转换的小数问题，0.264 应该是 1"。**诊断对了，但两个数各有各的根因**：

| 位置 | 看到的 | 根因 |
|---|---|---|
| 表格元素级面板「默认边框宽度（px）」 | 0 | `cellStyle.borderWidth` 从没设过 → 面板 `Number("") \|\| min \|\| 0` 落到 0；渲染实际走 `DEFAULT_BORDER_WIDTH` |
| 单元格面板「线宽（px）」 | 0.98 | `round2(mmToPx(0.26))`：存的是"约等于 1px"的 0.26mm，取整只留 2 位 |

**三处改动**：
1. `model.ts` 的 `DEFAULT_BORDER_WIDTH` 0.26 → **`25.4 / 96`（精确 1px）**。用字面量不用 import `MM_PER_PX`，是为了保持 model.ts 零运行时依赖（才能拿 Node 直接跑验证）。
2. `lib/utils.ts` 新增 **`roundPx`（1 位小数，与既有 `roundPt` 对称）** + `MM_PER_PX`/`PX_PER_MM`；两个面板的 px 显示统一走它（原先元素级是 inline `Math.round(*10)/10`、单元格级是 `round2`，同一根线两处显示不同的数）。存储的 mm 依然不 round。
3. `PropertyFieldConfig` 新增 **`fallback`**：未显式设置的字段显示**生效默认值**而不是 0。用在表格「默认边框宽度」（→1）与「默认单元格内边距」（→0.5，同一类问题同一个位置）上。**fallback 只影响显示、不写回元素**。顺带把该字段步进 0.1 → 0.5，与单元格面板线宽步进一致。

**浮点尾差**：`(25.4/96)×(96/25.4)` = `1.0000000000000002`，CSS 里就带这个尾巴；**没动渲染层**去补 round（浏览器照常解析，显示层已收敛成 1，不值得改渲染路径）。

**验证**（临时脚本跑真 `model.ts` + `lib/utils.ts`，Node 22，跑完已删）：26 条断言全绿 —— 新默认换算回 px 为 1 且显示 `1`；**旧常量 0.26 在旧口径下确实是 0.98（复现现象）**，新口径下历史数据也归正为 1；未设过 `cellStyle` 时回落 1px、元素级字段由 0 变 1 且 `cellStyle.borderWidth` **仍为 undefined**；内边距显示 0.5；回归项：0.5/1/1.5/2/3/10 px 经 `pxToMm→mmToPx→roundPx` 往返不变、0.1px 仍被 0.5px 下限兜住、默认线型颜色未动。`curl` 200（5 模块）、`eslint` 0 错误。

**未做浏览器验证**，需老板看两个面板的线宽框是否都显示 1。
