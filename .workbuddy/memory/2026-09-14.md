## 修复元素 resize/rotate 后立刻拖拽卡死（正确根因）
- **症状**：选中 text 元素，修改虚线框大小或角度后，立刻拖动位置，页面立即卡死；稍等片刻再拖就正常。与是否取消选中无关（取消选中只是表象上"恢复"）。
- **根因**：`ElementWrapper.vue` 的 `@pointermove/@pointerup/@pointercancel` 绑定在被拖动元素的 div 自身上。拖动（move/resize/rotate）时 `onPointerMove` 高频调用 `updateElement` 修改 x/y/width/height，元素自身随之移动/缩放。监听器绑在元素上 → 元素移动后指针与元素的相对位置变化 → 触发更多 pointermove → 形成「元素追着指针跑」的正反馈振荡，主线程被海量响应式更新打满而卡死。
  - resize/rotate 刚结束的瞬间元素几何变化最大，振荡最剧烈，所以「立刻 move」必卡死；稍等振荡衰减（元素稳定）后就正常。
  - 取消选中会移除 handle（v-if），DOM 结构变化打断振荡，所以「取消选中再拖」也正常——这是表象，不是根因。
- **修复**（`ElementWrapper.vue`）：
  1. 移除元素 div 上的 `@pointermove/@pointerup/@pointercancel`，只保留 `@pointerdown.stop`（用于启动拖动）。
  2. `begin()` 时把 `pointermove/pointerup/pointercancel` 用 `window.addEventListener` 挂到 window；`onPointerUp()` 时移除；新增 `onUnmounted` 清理，防止泄漏。
  3. 新增 `activePointerId` 追踪当前活动指针，`onPointerMove` 里校验 `activePointerId !== e.pointerId` 时忽略，避免跨手势残留事件串扰。
  4. `begin()` 里 `setPointerCapture` 前先 `releasePointerCapture`（try/catch 包裹），`onPointerUp` 里显式 `releasePointerCapture`，消除快速连击时的捕获状态竞态。
- **经验**：拖拽交互的 move/up 事件应挂 window（或 document），绝不能绑在被拖元素自身上，否则元素移动会反向影响事件派发形成振荡。
- **验证**：Playwright + CDP 精确注入事件，resize（189→57px）后立即 move，元素位移 (50,40) 与注入位移完全吻合，页面心跳/rAF 正常，无卡死。

## 修复「选中后 selection-box 不显示」（v-show on template 陷阱）
- **症状**：用户反馈"外面的虚线框没了"。选中 text 元素后看不到 8 个手柄、看不到蓝色虚线框，但拖动/缩放仍能正常工作。
- **根因**：上一轮优化 B 把 `<template v-if="selected">` 改成 `<template v-show="selected">` 想避免选中切换时 DOM 重建。但 **Vue 3 里 `<template v-show>` 是无效的**：
  - v-show 应用到 `<template>` 元素上，但 `<template>` 元素的浏览器默认 display 永远是 none（HTML 规范规定 template 不能被渲染为 block）。
  - v-show 试图把 display 切到 "" / "none"，但 template 的 default 就是 none，无论怎么 toggle 永远不可见。
  - 子节点 selection-box / handles 挂在 display:none 的 template 下，所以全部不可见（但 boundingClientRect 仍返回 0×0，DOM 里其实在）。
- **错误验证的教训**：上一轮我用 Playwright 验证「选中→取消→选中 → selection-box DOM 新增 0 次」就以为 v-show 起效了，但**只验证了 DOM 节点数量，没验证 bbox / display**——结果测错了。如果当时看一眼 `display` 就能立刻发现。
- **修复**：
  - 把 `<template v-show="selected">` 改成单根 `<div v-show="selected" class="selection-overlay">` 包住所有 overlay 子元素。
  - `.selection-overlay` 加 `position: absolute; inset: 0; pointer-events: none;`（默认不可点击，让 selection-box 撑满）。
  - `.handle` 和 `.rotate-handle` 加 `pointer-events: auto;`（恢复可点击）。
- **验证**（Playwright 通过 Pinia 直接设 selectedId="1"）：
  - `selection-overlay.computedStyle.display: "block"` ✓
  - `selection-box.bbox = wrapper.bbox = (334, 118, 189×189)` ✓ 完全吻合
  - 8 个 handles 全部 display ≠ none ✓
- **约定**：Vue 3 里 `v-show` **不能**用在 `<template>` 元素上（v-if 也不推荐但能 work）。需要"多个兄弟元素整体显隐"时，用单根 `<div v-show>` 包起来。如果某个 element 必须保持不被 v-show 影响（避免 DOM 重建），单独用 `<div v-show>` 切换显隐、把它作为兄弟节点放外面。
- **调试方法**：bbox 0×0 + computedStyle 的 display 不对时，第一时间看 `parentElement.tagName === "TEMPLATE"` —— 这是 Vue 3 的一个常见陷阱。

## 实施 transient state（拖动期间不写 store）
- **需求**：之前列出的优化项——Pinia 不适合做高频临时状态，会污染响应式图、触发所有 watcher 重算。
- **实施**（`ElementWrapper.vue`）：
  - 新增组件内 `transient = ref({ x: 0, y: 0, w: 0, h: 0, rot: 0 })`：拖动期间的 delta。
  - `wrapperStyle` computed 同时依赖 `props.element` 和 `transient`，视觉上是叠加。
  - `useDrag.onMove` 三个分支只更新 transient，**完全不调 `updateElement`**：
    - move: `transient.value = { ...t, x: dx/px, y: dy/px }`
    - resize: `applyTransientResize()` 算出最终 x/y/w/h，转成相对 snapshot 的 delta 写入 transient
    - rotate: `transient.value = { ...t, rot: delta }`
  - `useDrag.onEnd`：**一次性**把 `startEl + transient` 算出最终 patch，调用 `updateElement` 提交，然后清零 transient。
  - line 元素的 `start/end` 在 commit 时按最终 width/height 比例一次性写入（拖动期间 line 端点不实时缩放，已知 trade-off）。
- **关键收益**：
  - 拖动期间 store 不被写入，**任何 store watcher / 其它组件 / panel / history 监听都不会被高频触发**。
  - 只有当前组件的 wrapperStyle computed 依赖 transient，其他组件零额外开销。
  - 配合未来的 history/undo 系统：一次手势 = 一次 store mutation，**一次撤销记录**，而不是几十次。
- **验证**（Playwright 真实鼠标 + 拦截 `Object.assign` 计数 updateElement 触发次数）：
  - T1 点击选中 → updateCount=1（selectElement 不算 updateElement）
  - T2 拖动 body 移动（8 步）→ **updateCount=1** ✓ 期间不写 store，pointerup 一次性 commit
  - T3 resize（8 步）→ **updateCount=1** ✓
  - T4 rotate（8 步）→ **updateCount=1** ✓
  - T5 resize→立即 move → 跨手势无残留（transient 已被 onEnd 清零）✓
  - T6 点空白取消 → ✓
  - 无 JS 错误 ✓
- **约定**：组件内高频临时状态用本地 ref/store，**commit 到全局 store 推迟到动作结束时**。一次性手势（拖动、滑块、临时输入框）都应遵循这个模式。

## 画布页边距虚线（MarginGuides.vue）
- **需求**：在实际画布（designPanel）纸张上用虚线画出页边距，此前只在设置面板的小预览里有。
- **实现**：新增 `designPanel/components/MarginGuides.vue`，SVG 覆盖整张纸，`designPanel/index.vue` 里放在 `<ElementLayer />` 之后。
- **关键技术点**：
  1. **`vector-effect="non-scaling-stroke"`** —— 让 stroke-width 与 stroke-dasharray 都在**屏幕像素空间**计算，不受 viewBox(mm)→CSS(px) 缩放影响。于是 `stroke-width="1"` 恒等于 1px、**画布缩放时虚线粗细不变**。比手工换算 paintUnit（`1 / pxPerMm`）更简洁准确，这是本项目的更优解，设置面板预览里若有类似需求可改用此方案。
  2. **`pointer-events: none` 是硬要求** —— 辅助层绝不能拦截底下元素的选中/拖动/缩放（画布根目录有 `@pointerdown="deselect"`，一旦被拦截会导致选中失效）。
  3. **`z-index: 9999`** —— 元素 zIndex 从 0 起，参考线应始终可见（哪怕元素填满纸张），采用"参考线在最上层"的 Word/Figma 语义。
  4. **viewBox 用 mm 单位**（`0 0 widthMm heightMm`），所有坐标直接用 marginMm 值，无需换算；`preserveAspectRatio="none"` 因父容器比例与 viewBox 一致而不会变形。
  5. 内容区宽高钳到非负（`Math.max(0, ...)`），避免边距之和超过纸张时出现负宽高的非法 SVG 矩形。
- **视觉**：虚线框（opacity 0.55）+ 四角 L 形角标（opacity 0.9，边长=内容区短边 6%、钳制 2–12mm），与设置面板预览的工业风角标呼应。
- **未做（可后续加）**：显示/隐藏开关。目前常显；若嫌干扰可在 setting 面板加 toggle，或按"仅在选中/悬停时显示"处理。

## 边距线重设计 + 显隐开关（@frontend-design）
- **用户反馈**："边距框不好看" + 要显隐开关。
- **问题诊断**：原版用 `var(--primary)`（蓝）画边距线是**语义错配** —— 蓝在本项目代表"选中/激活"，会和元素选中框打架；纯虚线无层次，盖在元素上显得又重又廉价。
- **重设计方向**（工业实用 Industrial，延续项目既有语汇）：
  - **印刷裁切标记 crop marks**：内容区四角外、与框线留 3px 断口的短 L 形（臂长 9px）。用真实印刷行业语汇替代通用蓝色虚线框 —— 这是记忆点。
  - **45° 稀疏斜线阴影边距带**（hatching）：表示"留白/裁切区"的经典手法。只铺斜线不用实色遮罩，避免压暗底下的设计内容。
  - **配色退到后景**：三层中性灰阶（hatch 16% / 虚线 42% / 角标 75%），**刻意不用 primary**，把蓝留给选中态。背景参考语义就该退后。
- **关键技术**：
  - 边距线/角标用 `vector-effect="non-scaling-stroke"` → stroke-width 与 dasharray 都在屏幕像素空间，缩放画布时粗细恒定。
  - **但 SVG `<pattern>` 是 fill 不吃 non-scaling-stroke**，所以 hatch 的间距与线宽必须用 `mmPerPx = 1 / pxPerMm` 手工换算（屏幕 7px 间距 / 1px 线宽），否则缩小时会糊成一片。**组件因此新增 `pxPerMm` prop（画布坐标系知识属于画布，由父组件传入）**。
- **显隐开关**：store 加 `showMarginGuides: boolean`（默认 true，视图偏好不参与打印输出）；画布 `v-if`；设置面板页边距区 header 加眼睛图标按钮（Eye/EyeOff，22×22，关闭态降透明度去色，状态自解释）。

### 顺带修复：--hair 变量失去宿主（拆分 + 改 Accordion 引发的连锁 bug）
- **背景**：用户把纸张规格/页边距两个 section 改成了 **Accordion 折叠面板**（标题由 AccordionTrigger 提供），于是原来的 `.page-section` 容器没了。
- **问题**：`--hair: 1px solid color-mix(...)` 原本定义在 `.page-section` 上。宿主消失后，**子组件里所有 `border: var(--hair)` 变成无效声明 → 边框整片消失**（margin-xy / toggle-lock__track / margin-grid__cell 等全部受影响）。
- **修复**：利用 **CSS 变量可继承** 的特性，在 `setting/index.vue` 给 TabsContent 加 `.page-panel` class 并在其上定义 `--hair`，穿透到所有子/孙组件。scoped 下能命中是因为**子组件根元素会同时带父组件的 data-v 属性**。
- **教训**：CSS 变量的宿主元素被结构重构删除时，失效是**静默的**（无报错、只是样式没了）。重构容器结构后要全局搜一下 `var(--xxx)` 的定义是否还有宿主。

## BUG：横向标尺 0 刻度在特定缩放倍率下不对齐纸边
- **症状**：用户报告"93% 时对齐，103% 差 1mm"，且**只有横向**标尺有问题，纵向正常。
- **根因（用户的观察直接指向了不对称点）**：纸张定位横纵用了**两套不同的机制**
  ```js
  :style="{ left: '50%', transform: 'translateX(-50%)', top: `${paperY}px`, ... }"
  ```
  - 纵向 `top` = 显式 `paperY` → 与标尺 `originY = paperY - scroll.y` **同源**，恒定对齐。
  - 横向 `left:50% + translateX(-50%)` = **CSS 按容器实际宽度居中**；而标尺用 JS 算的
    `originX = paperX - scroll.x`，`paperX = (renderW - paperW)/2`，`renderW = max(contentW, viewW)`。
  - 两套基准只在"容器实际宽 == renderW"时一致。而 `viewW` 取自 `getBoundingClientRect().width`
    **含滚动条**，内容区 `min-w-full`(min-width:100%) 却相对 padding box = `clientWidth`
    **不含滚动条** → 纸张大到出现滚动条时，两基准岔开约半个滚动条宽（~7.5px），
    在 103% 下约 2mm。93% 时内容未溢出、无滚动条，所以恰好对齐。
  - **偏差随缩放变化**正是因为"滚动条有无"随纸张尺寸变化，而非缩放算法本身有误差。
- **修复**（`designPanel/index.vue`）：
  1. 纸张横向改用**显式定位** `left: ${paperX}px`，删掉 `translateX(-50%)` —— 与标尺 origin 同源，数学上保证对齐。
  2. `measureRuler` 改用 `rect.width - (offsetWidth - clientWidth)`：既**排除滚动条**
     （与 min-w-full 的 100% 基准一致），又**保留亚像素小数精度**（clientWidth 会取整）。
     单独用 `getBoundingClientRect` 或 `clientWidth` 都有偏差，必须组合。
  3. `paperX` 上加 JSDoc 警告：禁止改回百分比居中，写明原因。
- **教训（重要）**：
  1. **同一几何量只能有一个计算源**。用 CSS 百分比居中 + 另一处用 JS 算同一位置，必然在边界条件（滚动条、容器尺寸变化）下分叉。凡是"另一个组件需要知道这个位置"的，一律用显式定位。
  2. `getBoundingClientRect().width` **含滚动条**，`clientWidth` **不含但取整** —— 量取"可视区"要二者组合。
  3. 用户报告"某些缩放倍率下才不对"时，优先怀疑**随内容尺寸切换的状态**（滚动条出现/消失、容器溢出），而不是缩放算法本身的浮点误差。

## 旋转吸附（ElementWrapper.vue）
- **需求**：旋转元素时要有吸附（snapping）效果。
- **实现**：两层机制，与 Figma / PS / Sketch 一致：
  - **Shift → 吸附 15° 整数倍**（`ROTATE_SNAP_STEP = 15`）。Shift 是用户主动意图，不会误触发。
  - **未按 Shift → 接近正交角（0/90/180/270）时自动吸附**，阈值 `ROTATE_ORTHO_SNAP = 1.5°`。水平/垂直对齐是高频需求；1.5° 足够窄，不干扰 30°/45° 等常规角度。
- **关键实现点**：
  1. **吸附作用于绝对角度，不是手势 delta**。先 `startEl.rotation + delta` 得到绝对角，吸附后再减回 `startEl.rotation` 存进 transient。否则吸附点会相对手势起点漂移。
  2. **正交吸附要取最短旋转方向**：`diff = ortho - norm` 后做 `if (diff > 180) diff -= 360; if (diff < -180) diff += 360;`。否则 359° 到 0° 会被算成倒转 359°（而非前进 1°），元素会突然反转一大圈。
  3. `e.shiftKey` 从 `useDrag.onMove` 的原生 PointerEvent 读取 —— 每次 move 都是最新值，所以拖动中途按下/松开 Shift 都实时生效。
- **吸附必须可见，否则等于没做**：
  - 元素中心加 `.rotate-badge` 角度徽标（`v-if="mode === 'rotate'"`），数字跳到整数就是"吸附住了"的反馈。
  - 徽标在 wrapper 内会**跟着 `rotate()` 一起倾斜**，必须反向旋转同样角度保持水平：
    `transform: translate(-50%, -50%) rotate(${-currentRotation}deg)`。
  - 徽标用 `tabular-nums` 等宽数字，避免数字宽度变化导致徽标左右晃。
  - `isSnapped` ref → 吸附时 `.rotate-handle--snapped` 实心填充 + `scale(1.25)`，给"卡住了"的手感反馈。浮点比较用 `Math.abs(snapped - raw) > 1e-6`。
  - 手势结束（onEnd）记得重置 `isSnapped = false`。

## 设计网格 + 状态栏视图开关（PaperGrid.vue / statusLine）
- **需求**：页面上加一个切换，切换网格效果。
- **开关位置决策**：放**底部 statusLine**，不放设置面板。理由：网格/辅助线属于"看的方式"（视图偏好）而非文档内容，用户随时想切，一步就该够到；埋进折叠面板里每次都要展开。
  - 初版用 `ml-auto` 推到最右侧；**用户要求改到左边**，现紧跟 x/y 坐标显示（去掉 `ml-auto`，按钮作为 flex 直接子项自然左排）。后续标尺、安全区之类的视图开关都往这里追加即可。
- **网格设计**：单一均匀网格（10mm），一个 `<pattern>` 铺满整张纸。
  - 初版做了**两级嵌套 pattern**（10mm 细格 + 50mm 主线，与标尺 minor/major 呼应）：技巧是 major pattern 内部先用 `<rect fill="url(#grid-minor)">` 填满、再叠画自己的主线，一个 `<rect>` 就能铺满。
  - **用户反馈改成单一样式、去掉 50mm 主线** → 简化为单 pattern。若将来要恢复两级，注意 `MAJOR` 必须是 `MINOR` 的整数倍，否则两层会错位。
- **与页边距线的层级相反**：
  - 网格挂在 `ElementLayer` **之前**（背景纸纹，被元素盖住才符合直觉）
  - 页边距线挂在 `ElementLayer` **之后**（前景参考线，元素填满时也要可见）
- **缩放行为**：网格尺寸用 **mm**（viewBox 空间），随缩放一起放大缩小 —— 这是网格该有的行为（像放大一张方格纸）。线宽也用 mm（0.2 / 0.35），SCALE_MAX=200% 下约 0.4/0.7px 不会糊。
  - 对比：页边距线用 `non-scaling-stroke` 保持屏幕恒定 1px。**两者需求不同：网格是纸的一部分（应缩放），参考线是 UI（不应缩放）。**
- **store**：加 `showGrid: boolean`（默认 false，视图偏好不参与打印输出）。
- **约定**：视图显示类开关统一放 statusLine，用 `.view-toggle` 紧凑样式（18px 高、图标+短标签、靠底色表达开关态）；文档属性类设置放设置面板。

## 移动元素吸附到页边距线
- **需求**：拖动元素时边缘自动吸到版心（页边距）边界。
- **实现**（`ElementWrapper.vue`）：
  - `MARGIN_SNAP_PX = 6`（屏幕 px 磁吸半径），用 `/ pxPerMm` 换算成 mm 容差 —— **容差定义在屏幕空间**，这样缩放变小（pxPerMm 小）时 mm 容差自动变大，手感在各缩放级别下一致。
  - `snapAxis(pos, size, lines, tol)`：元素**两条边**（`pos` 与 `pos+size`）分别去够每条线，取距离最近的一组。**必须比较完取最近** —— 元素宽于内容区时两条边可能同时进入容差，逐个判断会导致左右拉扯。
  - 返回 `{ value, hit }`，`hit` 是命中线 id（用于高亮）；`snapMove` 汇总 X/Y 两个轴的 hits。
  - 按住 **Alt 临时关闭**（`e.altKey`），精细定位不被磁吸拽走 —— 主流工具通用约定。Alt 分支要返回空 hits，否则高亮会残留。
  - X/Y 线数组：`[marginMm.left, paper.widthMm - marginMm.right]` / `[marginMm.top, paper.heightMm - marginMm.bottom]`。
  - 接在 move 分支里：先算自由位置 `startEl + dx/pxPerMm`，再过 `snapMove`，最后存成相对 `startEl` 的 delta 到 transient（**transient 存的一直是 delta，不是绝对位置**）。
- **吸附高亮**：新增 `designPanel/composables/useSnapFeedback.ts`，**模块级** `ref<SnapLine[]>` 共享命中线状态。
  - 为什么不放 Pinia：高频瞬时视图状态、只有一个消费方（MarginGuides）、不该进文档数据。同一时刻只有一个手势，单例不会冲突。
  - `setSnapLines` 里做**内容相等短路**（长度+逐项比较），内容不变就不赋新数组 —— 否则 pointermove 每秒几十次会把 MarginGuides 无谓重渲染几十次。
  - `MarginGuides.vue` 的 `lines` 补上 `id` 字段，命中线加 `.margin-guides__line--active`：虚线转实线（`stroke-dasharray` 从 `3 3` 改 `none`）+ 主题色 + 全不透明。
  - 静息态仍用中性色（`--color-muted-foreground`, opacity .5），命中态才用 `--color-primary` —— 不违背"边距线是背景语义"的初衷，命中本就是"激活/对齐"语义。
  - `onEnd` 里 `clearSnapLines()`。
- **经验**：吸附类功能一定要配套视觉反馈。元素悄悄粘住会被当成卡顿或掉帧。
- **未做**：resize 手柄拖动时的边距吸附（可复用 `snapAxis`，待用户提）。
- **验证**：vite dev 200，编译产物含 snapMove/snapAxis/setSnapLines/activeSnapLines；eslint 三个改动文件零告警。

## 状态栏 x/y 读数宽度抖动
- **问题**：坐标读数随鼠标移动不停变宽变窄（9.0 → 10.0 差一位、进出画布变 "—"），把右边的开关推得左右跳，影响点击。
- **修复**（`statusLine/index.vue`）：把数字单独包一层 `<span class="readout__num">` 并 `min-width: 5ch`；前缀 "x: " 与单位 " mm" 是静态文本，于是整块宽度恒定。
  - **只给数字本体定宽就够**，不需要再给外层定宽 —— 外层 = 静态 + max(数字, 5ch) + 静态。
  - 用 `min-width` 而非 `width`：数值超长时撑开而不是截断。
  - `white-space: nowrap` 防止 flex 收缩时读数换行。
- **字体约定**：等宽 `ui-monospace, SFMono-Regular, "JetBrains Mono", Menlo, monospace` + `tabular-nums`，与设置面板 `.page-preview__dd--mono` 同一套。等宽下 `1ch` = 一个数字宽度，`5ch` 精确覆盖到 999.9。
  - 若用比例字体，也能靠 tabular-nums 让 `ch` 等于数字宽度，但 "x: " / " mm" 里的 m、空格是比例宽度，`ch` 预留就不精确了 —— 等宽字体更省心。
- **通用经验**：任何**实时刷动的数字读数**（坐标、角度、尺寸、百分比）都必须定宽 + tabular-nums，否则会把同行元素推着跳。这是本项目反复出现的坑（旋转徽标同理）。
