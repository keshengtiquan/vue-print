## 0. 结论先行（7 条）

1. **「接口」和「SQL」不是两条平行的路，而是同一个三层模型的两个末梢。** 业界的固定结构是 **数据源（连接） → 数据集（查询） → 绑定（谁消费）**，没有一家是两层的（因为一个连接下要挂 N 个查询）。「接口」和「SQL」的差别只在**数据集里的一个字段**（`type: "http" | "sql"`），上层模型、交互、绑定语法完全共用。
   → 所以**不要为两种方式写两套面板、两套模型、两套渲染**。

2. **纯前端不可能直连数据库，这是物理约束不是设计取舍。** 浏览器里的 JS 没有数据库协议栈、无法跨域、更关键的是**凭据必然会暴露给任何打开 F12 的人**。
   → 所以「SQL 写在哪、谁来执行」是本功能**唯一的硬架构决策**，见 §5。

3. **行业证据支持上一条：纯前端产品一律不做 SQL。**
   - **ActiveReportsJS**（葡萄城，纯前端报表设计器的标杆，主打"零服务端依赖 + 精准套打"）：数据源只接受 **REST API / OData / GraphQL / JSON**，**没有 SQL**。
   - **Stimulsoft Reports.JS**：浏览器端只接 JSON / REST / OData / Excel / 文件；MS SQL / MySQL / PostgreSQL 的直连能力放在**它的 Node.js 版本**里，而且明确说是"用来生成报告"的服务端形态。
   - **vue-plugin-hiprint**（开源、前端打印设计器，与我们形态最接近）：**干脆没有"数据源"这个概念**，只接收调用方传进来的 JSON。
   - 反过来，**做了 SQL 的那些（JimuReport / 帆软 / UReport2 / DataEase）全都自带后端**；DataEase 更极端 —— 它的 API 数据源必须**定时同步落库**才可用，不接受直连。

4. **建议一期只做"单数据集"**：一张表格 → 一个数据集 → 指定一行做明细模板；画布上的单值占位符取**该元素所绑数据集**的第一条记录。
   主从表（订单头 + 订单行 + 子表）是所有报表工具里最贵的一块（帆软要学"父子格"、FastReport 要注册 `DataRelation`、葡萄城要"表格嵌表格"），而**第一批真实场景（单据明细）单表就能覆盖 90%**。

5. **绑定语法建议就用 `{字段}`，不上表达式引擎。** 我们 `types.ts` 里已经写死"单元格内容是可含占位符的文本，不拆成两种结构"（表格文档 §1.5 约束 2），方向是对的。**一期不做 `{=SUM(...)}`** —— 计算放 SQL 里比放模板里合理，模板内引入表达式引擎等于自己造一门语言。

6. **行业的一对多机制是完全一致的：标记一行做模板，然后纵向复制。** 金蝶云星辰的文档原话值得直接引用：
   > "因重复数据行会根据数据第一行选定的字段自动打印多行，故无需再额外添加多行。"

   **没有一家是"给表格绑数据集就整表重绘"** —— 因为表头行、合计行不能被复制。
   ⚠️ **2026-09-20 老板拍板：表格的数据侧能力一期整体不做** —— 明细行复制、列映射全部移除，
   表格就是纯排版网格，取数留到导出 / 套打阶段（详见 **§11.16**）。
   v1 曾为此预留 `rowRoles` / `headerRows` / `detailRowIndex` 三个字段，加上后来加的 `columnFields`，
   **四个字段现已全部移除**；做导出 / 套打时按 §11.16 的"重建清单"补回。

7. **有一个隐藏需求必须现在定形状：套打的行数控制。** 用友/金蝶的单据打印标配这几项，而它们**不依赖多页渲染器**却**直接决定表格模型**：
   - 每页固定明细行数、明细不满**补空行**；
   - 合计行**仅末页显示**（还是每页都出）；
   - 每行**固定高度**（套打预印表格必须对齐纸上的格子）；
   - "套打"开关（只打数据、不打边框）。

   → 一旦上真数据，"明细 3 行"和"明细 30 行"打在同一张预印纸上要长得一样整齐。**如果一期不定这些字段，二期加会动渲染骨架。**

## 1. 竞品调研

### 1.1 三类产品走的是三条路

| 产品 | 形态 | 数据源类型 | **SQL 谁执行** | 一对多怎么重复 |
|---|---|---|---|---|
| **ActiveReportsJS**（葡萄城，商业） | **纯前端**，零服务端依赖，主打套打 | REST API / OData / GraphQL / JSON | **不支持 SQL** | 表格/矩表绑数据集 + 参数面板 |
| **Stimulsoft Reports.JS**（商业） | 浏览器端纯前端；Node 版可服务端 | 浏览器：JSON/REST/OData/Excel；**Node 端**：MSSQL/MySQL/PG/Firebird | 浏览器不做，**Node 版做** | DataBand |
| **vue-plugin-hiprint**（开源） | 纯前端打印设计器，**最像我们** | **无数据源概念**，调用方传 JSON | 不适用 | `table.field` 指向数组 + `columns[].field`，按数组自动出行 |
| **JimuReport**（积木报表，开源） | 自带 Service 端 | SQL（JDBC，28 种库含达梦/金仓/神通）+ API | **服务端** | 单元格「分组 + 扩展方向（纵/横）」 |
| **FineReport**（帆软，商业） | 自带服务端 | 数据库数据集 / 内置 / 文件 / 程序 | **服务端** | 单元格「扩展方向」+ **父格/子格** |
| **UReport2**（开源） | 自带服务端 | SQL / Spring Bean / JSON 等 10+ | **服务端** | 单元格 `Expand`(down/right/none) + 父格 |
| **DataEase**（开源 BI） | 自带服务端 | 数据库直连 / SQL / Excel / API（**API 需同步落库**） | **服务端** | 不适用（图表） |
| **AJ-Report**（开源大屏） | 自带服务端 | JDBC / ES SQL / **HTTP** | **服务端** | 不适用（图表） |
| **金蝶 套打设计器 / 用友 单据打印** | 自带后端（业务对象） | 业务对象字段（单据头 / 单据体）+ 系统字段 | 业务系统内部 | **表格首行 = 数据行模板**，按单据体记录数自动复制 |

### 1.2 五条可以直接抄的共性

1. **三层模型（连接 → 查询 → 绑定）**，没有例外。因为"连接"和"查询"要分开复用。
2. **点一下「解析 / 测试」就回字段列表**，然后**字段靠拖拽落到画布**。全行业统一交互，用户不用学。
3. **占位符与固定文本混排是刚需**（`单价：{单价} 元`），而不是"整格只能放一个字段"。
4. **一对多 = 标记模板行 + 纵向复制**（叫法不同：扩展方向 / DataBand / 数据行模板），且**表头/合计不参与复制**。
5. **参数化查询是标配**（打印时传单据 ID：`WHERE order_id = ${orderId}`），且**参数与系统变量是两套记号**：
   - JimuReport：`${id}` 是报表参数，`#{sysUserCode}` 是系统变量；
   - 金蝶：数据源里分「业务字段」与「系统字段」（当前页码 / 总页码 / 打印时间 / 打印人 / 数据行行号）。

### 1.3 三条我们必须自己判的差异（竞品帮不了）

**差异一：他们都自带后端，我们没有。**
→ 见 §5，这是唯一需要拍板的架构点。

**差异二：绑定落在"单元格"还是"元素"。**
竞品绝大多数是纯单元格模型（整个报表就是一张网格）。我们是**自由画布 + 自由元素**，所以绑定天然分两级：
- **元素级**（文本 / 图片 / 线条）：绑一个数据集，取**第一条记录**的字段 → 覆盖"单据头"场景（编号、日期、客户名）。
- **表格级**：绑一个数据集 + 指定明细模板行 → 按记录数**纵向复制** → 覆盖"明细区"场景。

**差异三：套打的"纸"是预印的。**
金蝶/用友的套打必须对齐印刷好的表格。这对我们的含义是：**行高必须可控到 mm、每页行数必须固定**（结论 7）。而纯前端报表工具（ActiveReportsJS）也要单独强调"精准套打"，说明这块是硬需求不是加分项。

## 2. 统一模型：三层

> 两种方式（接口 / SQL）**只在 `query` 分叉**，字段、参数、预览、绑定、渲染完全共用。

### 2.1 数据源（连接）

```ts
/** 数据源：连接信息。凭据一律不落模板，只存引用 id */
export interface TemplateDataSource {
  id: string;
  name: string;
  type: "http" | "sql" | "inject";
  /** sql：引用宿主侧预先登记好的连接（本模板只存 id/名，绝不存账号密码） */
  connectionRef?: string;
  /** sql：方言，用于前端语法提示与校验 */
  dialect?: "mysql" | "postgres" | "oracle" | "sqlserver" | "sqlite" | "dameng" | "kingbase";
  /** http：可选基地址，便于同域接口复用 */
  baseUrl?: string;
}
```

**关键点：模板里没有 host / port / user / password。** 这是安全底线，也是"模板可以随便外发"的前提。

### 2.2 数据集（查询声明）

```ts
export interface TemplateDataSet {
  id: string;
  /** 唯一标识符，供占位符引用：{订单明细.品名} 里的"订单明细" */
  name: string;
  label?: string;
  dataSourceId: string;

  // ---- 分叉只在这里 ----
  type: "sql" | "http" | "inject";
  /** type=sql：查询语句，允许 ${参数} 占位 */
  sql?: string;
  /** type=http：请求声明 */
  request?: {
    url: string;                      // 允许 ${参数}
    method: "GET" | "POST" | "PUT" | "DELETE";
    headers?: Record<string, string>; // value 允许 ${参数}（放 token）
    body?: string;                    // POST 用，JSON 文本模板
    /**
     * 取值路径：从响应体里取出"记录数组"。
     * 留空 = 响应体本身即数组；否则支持点路径 + 下标：data.list / data.rows[0].items
     * 刻意不引入完整 JsonPath 引擎（够用 + 零依赖）
     */
    resultPath?: string;
  };
  // ---------------------

  /** 参数：从 sql/url 里自动解析出的 ${name}，也可手工加 */
  params?: DataSetParam[];
  /** 字段：由"测试运行"回填的快照，也允许手工声明（离线设计 / inject 模式必填） */
  fields?: DataSetField[];
  /** 字段快照时间，用于提示"字段可能已过期" */
  fieldsRefreshedAt?: number;

  options?: {
    limit?: number;                          // 行数上限，默认 5000
    timeout?: number;                        // 超时 ms，默认 10000
    onEmpty?: "keepTemplate" | "blank";      // 无数据时：保留模板行静态内容 / 渲染空白
  };
}
```

### 2.3 字段与嵌套

```ts
export interface DataSetField {
  name: string;
  label?: string;
  type: "string" | "number" | "boolean" | "date" | "datetime" | "json";
  /** 默认展示格式：数字 #,##0.00 / 日期 YYYY-MM-DD / 中文大写金额 */
  format?: string;
  /**
   * 对象字段的子字段（address → city / street）。
   * - 子字段的 name 是从行根算起的**完整路径**（address.city），
   *   于是"拖出去当占位符 / 按路径取值"两处都能直接用 name。
   * - **只在纯对象上展开**：数组不展开（长度与元素形状都不固定，
   *   展开等于把字段树变成数据快照的翻版），保持叶子、整块 JSON 化。
   * - 展开层数上限 4（MAX_FIELD_DEPTH），防止深嵌套响应炸出上千字段。
   */
  children?: DataSetField[];
}
```

**字段解析的行业口径**（JimuReport / DataEase 都这样）：**自动推断 + 允许手工修正**。推断只做一层 —— 扫前 N 行的值，全 `number` → number，`YYYY-MM-DD` 形态 → date，其余 string。

## 3. 方式 A：接口（HTTP）

数据集编辑器里「接口」页签要做的事：

| 字段 | 说明 | 必要校验 |
|---|---|---|
| 请求方式 | GET / POST / PUT / DELETE | — |
| 请求地址 | 完整 URL，允许 `https://x/api/orders/${orderId}` | 必须 http(s)，**禁 `file:` / `javascript:`** |
| 请求头 | 键值表，value 支持 `${参数}`（放 token） | 屏蔽 `Host` / `Content-Length` 等危险头 |
| 请求体 | POST 用，JSON 文本模板 | 提交前做 JSON 合法性校验 |
| 取值路径 | 从响应里定位数组：`data.list` | 留空时若响应不是数组 → 明确报错"请指定取值路径" |
| 测试 | 「测试并解析字段」→ 回字段列表 + 前 20 行预览 | — |

**注意点**

- **响应结构千奇百怪，`resultPath` 是必须的**（DataEase 把它做成显式开关，可见其普遍性）。三种常见形态：
  - `[{...}]` 数组 → 留空；
  - `{ result: [{...}] }` → `result`；
  - `{ data: { list: [{...}] } }` → `data.list`。
- **CORS**：设计态直连会被跨域挡住。这是纯前端产品的固有限制（ActiveReportsJS 也要求数据端允许跨域或走自己的服务）。**降级方案见 §5 的 `auto` 模式**。
- **分页**：一期**只取一页**，不自动翻页合并。要合并多页请宿主侧合并好再给。
  ⚠️ 这是**接口分页**（一个接口返回的第 1/2/3 页），与打印的**分页渲染**是两回事。

## 4. 方式 B：SQL

### 4.1 核心设计：模板里存的是"声明"，不是"能执行的东西"

```jsonc
// 模板 JSON 里最终保存的（可安全外发）
{
  "id": "ds_order_detail",
  "name": "订单明细",
  "type": "sql",
  "dataSourceId": "src_erp",
  "sql": "SELECT p.name AS 品名, d.qty AS 数量, d.price AS 单价\nFROM order_detail d JOIN product p ON p.id = d.product_id\nWHERE d.order_id = ${orderId}\nORDER BY d.seq",
  "params": [{ "name": "orderId", "type": "string", "required": true, "source": "context" }]
}
// 注意：没有 host/port/user/password，也没有执行结果
```

### 4.2 执行链路

```
设计态 ─ 点「测试并解析字段」
   设计器 ──POST /api/print/dataset/test──▶ 宿主/后端
                                             ├─ 取连接（凭据在服务端配置里）
                                             ├─ 校验 SQL 只读 + 参数预编译绑定
                                             ├─ 执行（限行 + 超时 + 只读事务）
                                             └─▶ { fields: [...], rows: [...20条] }
   设计器 ◀────────────────────────────────┘  （只回字段 + 样本，不回全量）

预览态 ─ 同一接口（带真实参数）→ 回全量（≤ limit）→ 前端渲染

打印态 ─ 【建议】宿主自己执行。模板只是"说明书"。
```

**为什么打印态建议宿主自己执行**

- 打印往往是批量高频的（一次打 200 张单据），**每条都回浏览器再渲染是浪费**；
- 很多宿主本来就有权限体系（数据行级权限），走宿主能自动继承；
- 我们不需要为"服务端渲染"再造一套环境。

代价是**宿主需要实现一套约定的数据访问接口**（§5 给了契约草案）。

### 4.3 SQL 安全红线（必须硬性实现，不能只写在文档里）

| 红线 | 做法 |
|---|---|
| **只允许读** | 语句必须以 `SELECT` / `WITH` 开头；禁 DDL/DML；**禁多语句**（`;` 后非空即拒） |
| **禁注入** | 参数**一律预编译绑定**（`?` / `:name`），绝不字符串拼接。SQL 里只允许 `${name}` 且必须在参数位置 |
| **限行** | 强制包裹/注入 `LIMIT`（或方言等价物），默认 5000 |
| **限时** | 语句超时 10s，超时中断并返回明确错误 |
| **只读连接** | 宿主用**只读账号**接库；服务端用只读事务 |
| **白名单** | 连接必须在宿主侧**预先登记**，模板只能引用 id，**不能现填 host** |
| **不落库** | 执行结果不写进模板 JSON（体积 + 敏感） |

> 这几条不是"最好做到"，是"做 SQL 就必须做到"。少一条就等于把数据库交给了前端。

### 4.4 字段解析与 SQL 提示

JimuReport 的做法值得抄：SQL 编辑框旁边能看到**当前连接下的表清单和字段清单**，点空白处自动解析出参数字段。
→ **需要宿主提供一个"元信息"接口**（列出库表/字段），或让宿主在 `test` 接口里顺带回。

## 5. 谁执行 SQL —— 三种落地形态（**需要老板拍板**）

|  | **A. 宿主托管（推荐）** | **B. 自带轻量后端（Node BFF）** | **C. 宿主直接注入数据（最便宜）** |
|---|---|---|---|
| 形态 | 设计器只产出"数据声明"，宿主实现约定的 3 个接口 | 我们额外提供一个 Node 服务，实现这 3 个接口 | 模板不含查询；调用时把 `data + 字段 schema` 传进来 |
| SQL | ✅ 宿主执行 | ✅ 可执行 | ❌ 不需要（宿主自己查完再传） |
| 凭据 | 完全不出宿主 | 存在我们的服务里 | 不涉及 |
| 后端改造 | 中（要按规范做适配） | 低（开箱可用，但多一个部署产物） | **零** |
| 适合 | 已有业务系统的公司（目标客群） | 独立部署、没有后端的小客户 | **一期默认 / 演示 / 任意后端** |

**我建议：主线走 A，B 做成"可选参考实现"，C 当作"零后端也能跑通"的兜底。**

理由：
1. **C 是行业里最接近我们的那两个产品（hiprint、ActiveReportsJS 接 JSON）的实际做法**，而且**后端零改造** —— 宿主查好自己的数据、连同字段名一起传进来即可。这让功能**不依赖任何后端就能先落地、先验证**。
2. A 是长期形态（模板自包含，宿主一套适配所有模板）。
3. B 让"没有后端"的客户也能用，还可以当作 A 的参考实现（**接口层完全一样，将来切换零成本**）。

> 关键：**三种形态的接口层是同一套**。所以不要问"选哪个"，而是"先做哪个 + 契约怎么定"。契约定死之后，A / B / C 只是同一份接口层的不同后端。

### 5.1 约定的接口契约（草案）

```http
POST /api/print/dataset/test     # 设计态：不落数据，只回字段 + 样本
  { dataSource, dataset, params }  →  { fields: DataSetField[], rows: Row[], took: number }

POST /api/print/dataset/run      # 预览/打印：回数据
```

### 5.2 降级策略（必须有）

检测不到后端时，**数据面板整体显示"未接入数据服务"引导态，其余设计功能照常可用**。
绝不能因为没后端就白屏 —— 这与现在"导出/打印还是占位"是同一个处理原则。

## 6. 绑定层设计

### 6.1 语法（三套记号，别混）

| 写法 | 含义 |
|---|---|
| `{数据集.字段}` | 显式指定数据集。**插入字段时一律用这个形态**（§11.11）—— 只有它能表达"这个值来自哪份数据" |
| `{字段}` | 取**当前元素 / 表格所绑数据集**的字段。**旧写法**：仍照常取值，但新内容不要再这么写 |
| `{address.city}` | 对象子字段（前缀命中一级字段名 ⇒ 按子字段解释） |
| `{$page.index}` / `{$print.time}` | **系统变量**（`$` 前缀与字段区分） |
| 无占位符的纯文本 | 原样输出 |

> **为什么插入时一律带前缀**（§11.11 的结论）：`{品名}` 在"模板里只有一个数据集"时看着够用，
> 但模板一旦出现第二份数据 —— "单据头 + 明细"这种最常见的单据形态 —— 两种写法就会混在一起，
> 还得把画布上的占位符人工重写一遍。现在带上，以后一份都不用改。
> 前缀用的是数据集的**标识符**（面板上那个「标识符（占位符前缀）」字段，校验规则已排除空格 / 点号 / 花括号）。

> `$` 前缀这个约定，与 JimuReport 的 `${}` / `#{}` 分工、金蝶的「业务字段 / 系统字段」是同一个意思。

### 6.2 参数 vs 占位符（**千万别混**）

`${name}` 在本体系里**有两个完全不同的出现位置**：

| 出现位置 | 含义 | 谁替换 |
|---|---|---|
| `sql` / `url` / `headers` / `body` 里 | **查询参数**（要传给数据库/接口） | 执行侧（宿主/后端），**预编译绑定** |
| 单元格 `content.value` 里 | **字段占位符**（数据填进来） | 前端渲染函数 |

**一期只做三种参数来源**：`context`（打印入参，宿主传）、`sys`（系统变量）、`fixed`（固定值，调试用）。
**不做"用户在预览界面输入参数"** —— 那是报表的查询面板，是另一个功能。

### 6.3 系统变量清单（抄金蝶 + 用友）

| 变量 | 说明 |
|---|---|
| `$page.index` / `$page.count` | 当前页码 / 总页数（页码格式："第 X / Y 页"） |
| `$print.time` / `$print.user` | 打印时间 / 打印人 |
| `$row.index` | 明细行行号（表格内序号，等价于"序号"字段） |
| `$doc.title` | 单据标题 |
| `$company.*` | 企业信息（名称/地址/电话/传真），宿主提供 |

> `$page.count` 和"合计仅末页"这类，**依赖分页器**，一期只能给占位（见 §8 的说明）。

### 6.4 绑定落在哪里

```ts
// 所有元素共用（BaseElement 增加可选字段）
export interface ElementBinding {
  dataSetId?: string;   // 不填 = 未绑定，按静态内容渲染（拖字段进来时自动写入）
  filter?: string;      // 二期：过滤条件
}
```

```ts
// ⚠️ 表格侧**一期不补任何数据字段**（2026-09-20 拍板，见 §11.16）。
// TableElement 与数据绑定唯一的交点只有继承来的 BaseElement.binding。
{
  binding?: ElementBinding;

  // ---- 以下全部**不存在**，是"导出 / 套打阶段要补回来的一整套"（结论 7）----
  /** 声明哪一行是明细模板行，按记录数纵向复制 */
  detailRowIndex?: number;
  /** 前 N 行是表头，不参与展开、跨页时每页重复 */
  headerRows?: number;
  /** 列 → 字段名（长度 = cols）。空着的格子取该列的字段值 */
  columnFields?: (string | null)[];
  /** 每页固定明细行数；0/undefined = 不限制（按数据量展开） */
  detailRowsPerPage?: number;
  /** 明细不满 detailRowsPerPage 时是否补空行（套打对齐必须开） */
  padEmptyRows?: boolean;
  /** 合计行仅末页显示（false = 每页明细后都出合计） */
  summaryOnLastPageOnly?: boolean;
}
```

> **上面这一整块是给"将来做导出 / 套打的人"看的形状，不是现在的待办。**
> 2026-09-20 老板把表格的数据侧能力整体推迟了：面板上的「明细模板行」「列映射」「取数预览」
> 已全部移除（§11.16）。历史上"列映射"曾以两种身份出现过 —— 先是只写不读的死声明（§11.13），
> 后是取值期兜底（§11.15），两次都被判定为不该存在。**别照着旧章节再实现一遍。**
>
> 唯一继承下来的结论：**绝不引入"改了列映射就自动改写单元格内容"那条双写路径** ——
> "同一件事在两处各记一份、还可能互相覆盖"是 bug 温床。

### 6.5 一对多：一期规则（抄金蝶的简化版）

金蝶云打印模板的规则复杂度被压得很低，可直接抄：
> - **画布上的单值字段**（不在表格里）→ 取匹配记录的**第一条**；
> - **绑在数据表格里的字段** → 把匹配的**全部记录**都展示出来。

对应到我们：

1. **不存在"主数据集 / 默认数据集"**（老板 2026-09-20 拍板，实现已按此改）。元素绑谁，等于"用户往它里面拖了哪个字段"——`FieldNode` 的拖拽载荷里本来就带着 `dataSetId`，落点端把它写进 `element.binding.dataSetId`。
   - 没绑定的元素**按静态内容渲染**，刻意不做任何猜测性兜底：兜底一旦猜错，画布上显示的是**另一份数据**且没有任何提示，比"什么都不显示"难排查得多。
   - 拖字段时若元素已绑着别的数据集，**改绑（后拖的赢）**。一期不支持一个元素跨数据集取数；"追加了占位符却渲染不出值"比"改绑"更难排查，而后者在绑定面板上直接可见。
2. 画布上的文本/图片元素里的占位符 → 取**该元素所绑数据集**的**第一条记录**。
3. 表格元素：**一期不展开、不取数** —— 它是纯排版网格，画布上渲染的就是模板行本身（§11.16）。
   往单元格拖字段仍然有效，但那是"把 `{数据集.字段}` 写进这一格"，与在文本元素里写占位符
   是同一件事，**不产生任何行列变化**。
4. **表头不复制、合计不复制**这套规则属于**导出 / 套打阶段**：那时用 `detailRowIndex` +
   `headerRows` 声明（形状见 §6.4 的"要补回来的一整套"）。
5. 渲染顺序同样是导出阶段的事：先按声明把表格切成 `[表头区][明细模板行][合计区]`，
   再扩展明细行，最后按 `detailRowsPerPage` / `padEmptyRows` 补齐。
6. **"表头不复制"与"跨页表头重复"不矛盾**：单页内表头只出现一次（不随明细复制）；一旦明细跨页，表头由**分页器**在每页顶部重画。前者是绑定的职责，后者是分页的职责。

**一期明确不做**：多数据集 JOIN、子表嵌在父表行里、`filter` / 关联条件、跨表聚合。

### 6.6 渲染必须收敛成一个纯函数

```ts
/**
 * 唯一的占位符实现。
 * 预览态、导出、打印都调它 —— **设计态画布不调**（见 §6.7）。
 * ⚠️ 当前**一处调用都没有**：面板的「取数预览」也已移除（§11.16）。
 * 它是留给渲染态的，别因为"眼下没人调"就当它多余。
 */
export function renderTemplate(
  value: string,
  ctx: { get(field: string): unknown; getSys?(name: string): unknown; format?: string },
): string;
```

**凡是"要把 `{字段}` 变成值"的地方，必须走这同一个函数** —— 否则"面板里看着对、
打印出来空"是必然的。字段名带空格、嵌套字段、缺值、空字符串 vs 无值、
`{字段}` 与 `${参数}` 混排……每份手写实现迟早会在这些边界上分叉。

但要先分清**谁需要把占位符变成值**：只有"给人看数据"的地方需要。
设计态画布恰恰不需要 —— 它连调用都不该出现（§6.7）。

### 6.7 设计态画布显示什么 —— **已定：一律显示占位符原文，不显示数据值**

> **设计态画布是排版视图，不是数据预览。** 内容里写 `{品名}`，画布上就显示 `{品名}`，
> 一个字符都不替换。**当前整个应用里没有任何地方显示字段值** —— 面板的「取数预览」
> 也已按老板要求移除（§11.16）；"把 `{品名}` 变成值"这件事属于预览 / 打印态。
> 预览 / 打印态才用真数据替换。

三条理由：

1. **排版是设计态唯一要回答的问题**。字宽、换行、对齐都不该随"取到什么值"而抖 ——
   否则"照着一份数据调好的版，换份数据就错位"，而这正是设计器最怕的事。
2. **占位符本身就是要看的信息**。`{品名}` 明明白白写着这一格引用了哪个字段；
   换成值之后反而看不出这里绑了什么、到底绑没绑。
3. **它和表格文档 §1.5 约束 2 是同一条口径** —— 那里原文就写着
   "`content.value` 允许含 `{品名}` 这类占位符，**设计态原样显示**"、
   "不要加占位符校验 / 转义 / **高亮**逻辑，`{品名}` 在设计态就当普通字符渲染"。
   本来就该如此，实现时一度偏离成"画布渲染字段值"，此处纠正并写死。

**落到代码的两条硬约束**：

- `renderTemplate` **不在画布层被调用**。看门狗是一条 grep：
  `grep -rn "renderTemplate" src/components/design/designPanel/` 应当**零命中**。
- **不给占位符加任何视觉标记**（底色、虚线框、加粗）。约束 2 点名了"不要加高亮"：
  加了就改变字宽、影响排版测量，而这条约束的全部意义就是"当普通字符"。

**明细行扩展仍然保留**：它表达的是**行数 / 行高 / 会不会撑出纸张**，
属于排版信息，与"是否显示字段值"是两件事。代价是画布上会出现 N 份内容相同的行 ——
这恰好正确表达了"这一行会重复 N 次"。

## 7. 交互设计

### 7.1 四个新界面

| 界面 | 位置 | 内容 |
|---|---|---|
| **数据面板** | 左侧栏新增「数据」页签（与素材台并列） | 数据源列表（可折叠）+ 数据集列表；右键重命名/复制/删除；底部「+ 新建数据集」 |
| **数据集编辑器**（弹窗） | 从数据面板打开 | 顶部切「接口 / SQL」；中部按 §3 / §4 的表单；底部「测试并解析字段」+ 字段/数据预览表格 |
| **字段树** | 数据面板下半部（选中某数据集时） | 字段树（可拖），拖到画布元素或单元格即完成绑定 |
| **绑定面板** | 右侧属性面板新增「数据」分组 | 选数据集 + 占位符插入器（文本 / 图片）。**表格只剩"选数据集"这一项** —— 明细模板行 / 列映射 / 取数预览已移除（§11.16），套打行数控制属 P2 |

### 7.2 三条关键交互链路

1. **字段拖到单元格** → 在 `content.value` 末尾追加 `{数据集.字段}`，同时**整张表自动绑上**该字段所属的数据集。
   画布上**原样显示这段占位符**（设计态不渲染值，§6.7 / §11.10）。
   ⚠️ 它只是"往这一格写一段文本"，**不产生任何行列变化、不触发任何表格取数**（§11.16）。
2. ~~**表格绑定明细行**~~ —— **已移除**（§11.16）。表格没有"数据行"概念，画布渲染的就是模板网格本身。
3. ~~**列映射**~~ —— **已移除**（§11.16）。它要生效必须"列 → 字段"与"行 → 记录"**两个映射同时成立**，
   而一期不做明细行 ⇒ 列映射没有落点（§11.15 已论证过这一点）。
   列的增删仍走表格右键菜单 / 行列控制（`insertCol` / `removeCol`），与数据绑定无关。
   v1 的"一键按字段顺序生成列"也早已移除（§11.13）。

### 7.3 设计态的"假数据"从哪来

- 数据集有**样本数据快照**（测试时拿到的前 20 行）。
  **只存内存 + 模板里存前 3 行**，避免模板体积膨胀。
- 表格扩展预览**最多画 5 行**（超出显示"…共 N 行"），避免设计态卡顿。
- 表格下方给一条**状态提示**（"明细 N 行 · 画布示意 M 行 · 约 K 行超出纸张"），比给行角色调色带干扰小、信息更全。

> ⚠️ 后两条**都建立在"表格会扩展"这个前提上**，而 §11.16 已取消表格的数据侧能力 ⇒ 随之作废。
> 样本快照本身仍然保留：字段解析与将来的取数都靠它，"测试并解析字段"仍然依赖它。

## 8. 分期计划

| 期 | 内容 | 能否自证价值 |
|---|---|---|
| **P0** | 数据集管理：接口 + SQL 两种类型的配置、测试连接、字段解析、样本预览（**不落元素绑定**） | ✅ 面板里就能看到真数据 |
| **P1** | 绑定落地：文本 / 图片 / 单元格占位符（**表格明细行复制、列映射、设计态填充预览已按 §11.16 移出本期**，随导出 / 套打一起做） | ✅ 字段能拖进模板并留下占位符 |
| **P2** | 参数（打印入参 + 系统变量）+ 字段格式化 + **套打行数控制**（每页固定行数 / 补空行 / 合计仅末页 / 固定行高） | ✅ 套打对齐预印纸 |
| **P3** | 多数据集主从关联 + 分页 + 跨页表头重复 | 依赖多页渲染器 |

### 关于"多页渲染器"的定位（重要，别搞反依赖）

数据绑定解决"**内容有多少、长什么样**"（取数 → 占位符替换 → 明细行复制），全部在**单页内**完成与验证；
多页渲染解决"**内容放到哪一页**"。两者**正交**，**P0 ~ P2 不被它阻塞**。

它只卡 P3 的分页与跨页表头重复。模型里目前**只剩 `allowBreakAcrossPages` 一个预留字段**（`headerRows` 已删，§11.14；重建设想见 §11.16），数据期元素 `height` 降级为"设计时快照"。

**但要提前知道一个连带后果**：绑定做完、分页器未到位时，明细条数超过单页容量的部分会**溢出到纸张外**。
届时不静默裁切，而是在画布与预览给出明确提示，避免被当成绑定 bug。

**另外**：P2 的"每页固定行数 + 补空行"能在单页内实现（把明细区当成 N 个固定槽位），**不需要分页器**。这是把它提到 P2 的原因 —— 它才是套打真正每天要用的东西。

### 四条不能违反的既有铁律（来自项目记忆）

1. **`cells` 只能整包替换**（`updateTable(id, mutator)`），**绝不点路径写**。
   绑定是嵌套对象（`binding`），写入走 `updateElement` 且**必须深拷贝** —— 数据所有权铁律，已踩两次。
2. **第 2/3 层状态的消费必须过"哪张表"的门禁**（`tableEditingId === element.id`）。
   表格上的任何面板级写入（当前只剩"绑哪个数据集"）同样要带门禁，否则两张表会同时被改。
3. **改表格总宽/总高走 `updateElement`**（内部 `scaleTracks`），**整表行高列宽走 `updateTable`**。
   "按字段生成列"曾同时改列数与列宽 ⇒ **结构变更必须走 `updateTable`**（该功能已移除，见 §11.13）；
   列映射（`columnFields`）曾走 `updateTable`，只是为了在 mutator 里读到最新 `cols` 做长度对齐、
   **不涉及结构** —— 它也已移除（§11.16）。这条现在纯粹是"将来若再加列级声明"的提醒。
4. **画布只渲染模板网格，不做任何数据扩展**（明细行机制已整块移除，见 §11.12）。
   这条以前写作"明细行扩展只在非编辑态生效"，理由是 `rowOffsets(el)` 只认模板行、DOM 里多出的行会让分隔线热区与行把手指错行。

### 11.7 需要老板手点一遍的链路（自动化覆盖不到）

自动化只到"编译通过 + lint + 静态核对"。下面几条是交互，需要真机点：

1. 左侧「**数据**」页签 → 新建数据集 → 填一个允许跨域的接口
   （如 `https://jsonplaceholder.typicode.com/users`，取值路径**留空**）→ 点「测试并解析字段」→ 字段列表与数据预览应出现。
2. **拖一个文本素材到画布 → 从字段树拖一个字段进去（或在右侧面板「插入字段」下拉里选一个）** →
   内容末尾出现 `{数据集1.字段}` —— **带数据集标识符，两条路都应如此**（§11.11）；
   画布上**显示这段占位符原文、不显示值**（§11.10）；
   并且**右侧「数据绑定」里的数据集应自动变成该字段所属的那个**（§11.9）。
3. 拖一个**表格** → 把字段拖进某个单元格（整张表绑到该字段所属的数据集，也可在面板上选）→
   画布上表格**结构不变、行数不变**，格子里是 `{数据集1.字段}` 原文。
   表格的「数据」分组里**只应有「数据集」一个下拉** —— 「明细模板行」「列映射」「取数预览」
   都不该存在（§11.12 / §11.16）。
4. **双击表格进入编辑态、再退出** → 行数 / 行分隔线热区 / 行把手**始终与模板网格一致**。
   （扩展行没了之后，表格几何不再有"编辑态要特判"的例外，这一条是回归确认。）
5. 把字段拖到**处在编辑态的单元格**上 → 该格内容末尾出现 `{数据集1.字段}`，**且整张表绑到该字段所属的数据集**；
   拖到**图片元素**上 → `src` 变为 `{数据集1.字段}`，图片元素同样自动绑定。
   ⭐ **图片这条要特别看一眼**：含占位符时图片位置应显示这段原文、
   **不出现裂图、控制台不应有占位符引起的 404 请求**（§11.10）。
6. **删除数据集** → 引用它的元素绑定应被清掉（元素不再显示"已绑定"）。
7. **全应用都不显示字段值**：随手在文本元素内容里写一个 `{不存在字段}` → 画布上原样显示这段花括号；
   再给一个元素拖上真字段 → 画布上**依然**是 `{数据集1.字段}` 原文；
   右侧属性面板的「数据」分组里**也不该再有任何显示值的区域**（§11.16）。
   这一条是 §11.10 的核心，也是"设计态 = 排版视图"这句抽象说法唯一能被眼睛验证的地方。
8. 顺带确认：**打开数据集编辑器弹窗时，画布边距线不再盖住弹窗**（`isolate` 那个修复）。

### 11.8 已知限制

- **直连模式受浏览器 CORS 限制**，跨域接口会报"请求失败：可能是目标接口不允许跨域"。
  生产环境请配置宿主数据服务（`src/api/dataset.ts` 的 `dataServiceConfig.baseUrl`）。
- `{数据集.字段}` 的前缀**插入时一律带上**（§11.11）；取值侧对前缀仍是**宽松校验** ——
  前缀与本数据集不符时才返回缺值（画布上显示原样占位符），旧的无前缀 `{字段}` 也照常取值。
  等做多数据集关联时才会真正收紧。
- **表格的数据侧能力（明细行纵向复制、按记录数撑高、套打行数控制）一期全部未做**，
  连"哪一行是明细行"的声明字段都没有 —— 画布只渲染模板网格。这部分要么不做，
  要么在做导出 / 套打时整体设计，见 §11.12。

### 11.9 追加改动：去掉"主数据集"，改为"拖字段即绑定"（2026-09-20 下午）

**老板决策原话**："我不想引入这个主数据集或默认数据集的概念。我从字段那里拖动到元素上，是那个元素的那他绑定的就是那个数据集的。不会存在没有数据集的情况。"

**背景**：v1 引入了 `primaryDataSetId`（元素"没显式绑定"时的兜底默认值，抄金蝶的单据头规则）。
复核确认它**只是"没绑时的默认值"，不是"唯一的数据集"**，全项目仅 3 个消费点且都在兜底。但这个概念有两处实质问题，故整体移除：

1. **命名与语义不符** —— 叫"主"容易被读成"唯一 / 有从属关系"。
2. **`??` 兜底会把"悬空引用"静默降级** —— `dataSetById(id) ?? primaryDataSet` 无法区分"没绑"和"绑了但数据集不存在"。
   于是模板 JSON 被手工改过、将来跨模板复制粘贴等场景下，元素会**静默改用另一份数据**渲染：
   用户以为在用 A、看到的却是 B，且没有任何提示。

> 但**关于表格明细行扩展、面板「取数预览」的部分已被后续章节推翻**：
> 明细行机制当天稍后整块移除（§11.12），「取数预览」也在当晚移除（§11.16）。

**老板决策原话**："设计页面元素绑定数据后不需要显示数据值出来。要把它的标识符占位符显示出来。"

#### 这是**回归既定约束**，不是新需求

复核时找到两处早就写好的原文，而当时的实现与它们背离：

| 出处 | 原文 |
|---|---|
| `docs/table-feature-design.md` §1.5 约束 2 | 单元格 `value` "允许含 `{品名}` 这类占位符，**设计态原样显示**"；"**不要加占位符校验 / 转义 / 高亮逻辑** —— `{品名}` 在设计态就当普通字符渲染" |
| 本文档 §6.7（v1 就写了） | "**设计态始终显示写进去的静态文本（占位符原样保留）**，即'空数据 = 不填充，保留设计内容'" |

§11.2 里"已接线的渲染（`TextElement` / `ImageElement` / `TableElement`）"是按"画布显示字段值"做的，
**与上面两条冲突**。本次统一到约束一侧。

#### 行为变化

| 位置 | 改前 | 改后 |
|---|---|---|
| 画布 · 文本元素 | `{品名}` → `曲面显示器` | `{品名}` → **`{品名}`** |
| 画布 · 表格单元格 | 同上 | 同上 |
| 画布 · 图片元素 | `{商品图}` 被当 URL 请求 → 裂图 + 一屏 404 | 显示 `{商品图}` 原文，**不发请求** |
| 面板 · 「效果预览」 | 显示值 | （当时）改名「取数预览」、继续显示值。**现已整块移除（§11.16）** |
| 表格明细行扩展 | 扩展 N 行，每行吃自己那条记录的值 | **仍然扩展 N 行**，但每行内容都是同一份占位符原文 |

**为什么图片那格要单独处理**：`<img src="{商品图}">` 会被浏览器当成**相对路径**发一次请求 ——
控制台一屏 404、图片位置显示裂图，比什么都不显示更糟。所以含占位符时 `displaySrc` 返回空串，
走"显示占位符文本"的分支。

**为什么明细行扩展保留**：它表达的是**行数 / 行高 / 会不会撑出纸张**，属于排版信息，
与"显不显示字段值"是两件事。代价是画布上出现 N 份内容相同的行 —— 这恰好正确表达了
"这一行会重复 N 次"。若老板要的是"完全不扩展"，把 `TableElement` 的 `expandable` 置 false 即可（一处）。

**为什么（当时）保留面板的取数预览**：画布不显示值之后，"绑定到底配对没有、能取到什么值"
就只剩这一个地方能回答 —— 它的价值反而变高了（也因此从"效果预览"正名为"取数预览"）。

> ⚠️ **这条理由当晚被推翻**（§11.16）：老板的判断是"面板预览不该存在" —— 它和明细行绑在一起，
> 养出一套"只有预览看得见"的规则，而设计态要回答的只是排版。所以取值预览整体移除，
> "取到什么值"留到预览 / 打印态去回答。

### 11.11 插入的占位符一律带数据集标识（2026-09-20 下午）

**老板决策原话**（截图指向单元格里的 `{name}`）："我的意思是这里应该把数据集的标识符带上。"

#### 问题在哪

字段拖进画布后写的是光秃秃的 `{name}`。这在"模板里只有一个数据集"时能用，
但它丢掉了一个信息：**这个值来自哪份数据**。而 `{数据集.字段}` 本来就是
`lib/template.ts` 定义的合法写法（§6.1），只是一直没被插入路径用起来。

代价会在"单据头 + 明细"这种最常见的形态上一次性暴露：模板里出现第二份数据之后，
画布上所有 `{字段}` 都有了歧义，而唯一的修法是**人工把每个占位符重写一遍**。

#### 改动

| 文件 | 改动 |
|---|---|
| `data/useDataBinding.ts` | 新增 `fieldToken(field, dataSetId)`：用 `dataSetById(id).name` 拼 `{数据集.字段}`，拿不到数据集时退回 `{字段}`。三个插入函数内部改用它 —— **调用点签名不变** |
| `data/FieldNode.vue` | 拖拽的 `text/plain` 兜底也走 `fieldToken`（原来手拼 `{字段名}`），让**兜底文本与真正插进画布的内容形态一致** |
| `data/DataPanel.vue` | 「已插入 …」提示文案复用 `fieldToken`，避免"提示说插了什么"与"实际插进去什么"对不上 |

`BindingSection.vue` 的「插入字段」下拉在 §11.9 那轮已经传了 `dataSetId`，**零改动**。

#### 为什么前缀取 `name` 而不是 `label`

- `name` 的面板名就叫「**标识符（占位符前缀）**」，`types.ts` 的注释是
  "唯一标识符，供占位符引用：`{订单明细.品名}` 里的'订单明细'"。
- 它的校验 `isValidDataSetName` = `/^[^\s{}.$][^\s{}.$]*$/`，**排除了空格、点号、花括号、`$`** ——
  正好就是"放进占位符不会切断解析"的那套字符。**点号尤其关键**：`splitTokenKey` 按
  **第一个点**切，名字里带点会让 `{订单明细V2.品名}` 这类前缀被切错。
- `label` 是给人看的显示名（允许空格、允许重名），拿它当前缀会直接破坏解析。

#### 取值侧一行没改

`context.ts` 的 `buildRowContext` 早就按"前缀与 `dataSetName` 比对"实现了：
相同 ⇒ 正常取字段；不同且不是一级字段名 ⇒ 返回缺值（画布上显示原样占位符）。
**旧的无前缀 `{字段}` 也照常取值**（`prefix` 为 `undefined` 时走同一条正常路径），
所以画布上已有的旧占位符**不需要迁移、也不该自动改写**（那是替用户改内容）。

#### 收敛性自查（新增一条看门狗）

全项目**只有一处**在构造 `{...}` 文本 —— `fieldToken` 自己：

```bash
grep -rn '`{\${' src --include=*.ts --include=*.vue
# 只应命中 useDataBinding.ts 里 fieldToken 那一行
```

#### 验证（沿用 §11.5 的方式）

- `npx vite` + `curl` **17 个模块全部 200**。
- `npx eslint`（改动范围）**0 problem**；全仓仍是那 1 个既有 error（`views/dashboard/index.vue:250`）。
- `fieldToken` 共 5 个消费点（三个插入函数 + 面板提示 + 拖拽兜底），无遗漏。

1. 问「列映射是干嘛的」→ 复核发现它是**只写不读的死声明**（§11.13 把它当"保留"留下的）。
   我建议删，**老板选择的是"接通成真正的取数路径"**。
2. 追问「数据行在哪显示」→ 老板选**面板整表预览**：画布保持只显示占位符（§11.10 继续有效）。

**为什么"接通"必须恢复"行 → 记录"**：

一个数据格拿到值，需要**两个映射同时成立**：

| 映射 | 本次之前的状态 |
|---|---|
| 列 → 哪个字段 | ✅ `columnFields` 已声明 |
| 行 → 哪一条记录 | ❌ **根本不存在** —— 表格只有模板网格 |

§11.12 删掉明细行之后，`rowViews` 就是 `gridCells(el)` 的直接映射，一行不多一行不少。
于是"整列取数"没有落点：3 行 × 4 列的表格、第 2 列绑 `单价`，三个格子取的是**同一条记录的同一个值**。

**结论：列映射不可能单独接通 —— 它必须和"行 → 记录"一起才成立。**

**设计（最小必要集）**：

1. **只恢复一个字段**：`TableElement.detailRowIndex?`（明细模板行的行号，0 起）。
   - `undefined` = **整表静态**：一行不多一行不少，与本次之前的行为**完全一致**。
     不声明就不展开是刻意的 —— 隐含约定（"第 2 行自动当明细"）会让数据行数莫名变化而无从解释。
   - 它之前的行 = 表头、之后的行 = 固定尾行，都只出现一次。
   - **刻意不恢复 `rowRoles`**：那套"表头 / 明细 / 合计"三段角色是确认过的死数据，
     "与明细行的相对位置"已经能表达三段，不必再声明一套没人读的角色。

2. **取值优先级（两个入口、一条取值路径）** —— 唯一实现：`src/components/design/data/tableRender.ts`
   - 格里**有内容**（含 `{占位符}`）→ 按当前记录的上下文渲染。**静态内容优先**：写了"合计"就不会被列映射覆盖。
   - 格里**是空的** 且该列有 `columnFields[c]` → 取该字段的值。**列映射的落点就在这里。**
   - 都没有 → 空。

   ⚠️ 这与 §6.4 那句"刻意不引入第二条隐式写入路径"**不冲突**：列映射是**取值期兜底**，
   **绝不回写单元格内容**。被禁止的是"改列映射就自动改写格子里的文字"那种双写，不是取值兜底。

3. **可见性**：画布**不变**（仍只显示 `{字段}` 占位符）。新增 `BindingSection.vue` 的**整表取数预览**，
   它与将来的导出 / 打印共用 `renderTableRows()` —— 展开逻辑只有一份实现，
   于是"预览里看着对、打出来不对"这类 bug 从结构上不可能发生。

**顺带修掉两个静默 bug**（都是"声明与实际脱节"，与 §11.14 同一个病根）：

| bug | 症状 | 修法 |
|---|---|---|
| `syncColumnFields` 是**无人调用的死代码** | 删掉第 1 列后，第 2 列的下拉显示的是原第 2 列的字段（映射整体错位一位） | 同步挪进 `insertCol` / `removeCol` 内部 —— 结构变更的维护与结构变更写在同一个函数里，跨层调用只会再断一次；`syncColumnFields` 删除 |
| `detailRowIndex` 没有行号维护 | 插 / 删行后明细行指向错行，或指向已被删掉的行 | `insertRow`：插在它前面则 +1；`removeRow`：删掉它则**清掉声明**（不钳到相邻行）、删在它前面则 -1 |

**改动清单**：

| 文件 | 改动 |
|---|---|
| `design/types.ts` | 恢复 `detailRowIndex?`；`columnFields` 注释从"声明、不会自动填值"改为"兜底声明" |
| `data/tableRender.ts` | **新增**：展开 + 取值的唯一实现（纯函数、与 DOM 无关） |
| `table/model.ts` | `insertCol` / `removeCol` 同步 `columnFields`；`insertRow` / `removeRow` 维护 `detailRowIndex` |
| `data/useDataBinding.ts` | 删除 `syncColumnFields`（§11.13 保留清单中该项作废） |
| `setting/element/BindingSection.vue` | 新增「明细模板行」下拉；表格的「取数预览」升级为整表预览（超过 10 行时保留全部非明细行、只截明细行）；列映射文案改为"只填空格子" |
| `designPanel/.../TableElement.vue` | 只改注释：`pointToTemplateCell` 那句"把展开出来的预览行折算回模板行"是 §11.12 的遗留描述，代码里早已没有折算 |

**未做（明确）**：

**验证**：

### 11.16 表格的数据侧能力整体移除：明细模板行 + 列映射 + 取数预览（2026-09-20 晚）

**老板决策原话**：

1. 先指方向："你理解偏离了。我让你解决的是，列映射这里修改了字段后，画布上也要跟这个改，
   同样画布上拖入了一个字段，这里的映射也跟这改。**把明细模板行和预览给我删掉。我不想要这两个东西。**"
2. 追问"改列映射时画布上该改哪些格子"（整列 / 只改没写死文字的 / 只替换已有占位符）之后，
   老板收回整条需求："**那我想错了。直接把列映射删掉把。**"
3. 追问"文本元素的取数预览留不留"，答："**也删掉**"。

#### 为什么推翻 §11.15

§11.15 的技术前提**没错**：一格要取到值，需要「列 → 字段」与「行 → 记录」两个映射同时成立，
而"行 → 记录"当时根本不存在 ⇒ 列映射只能空转。它给的解法也没错（恢复明细行展开）。

错的是**层次**：为了给一个面板下拉找出落点，在**设计态**里养了一整套"只有面板预览看得见"的
展开规则（`detailRowIndex` + 一张 10 行上限的只读小表）。而设计态要回答的只有**排版**——
表格有几行、行高多少、会不会撑出纸张，这些**不依赖样本数据**。取数是**渲染态**的事。

换句话说：**一个"改了画布上看不见、只有预览里看得见"的功能，本身就说明它不属于设计态。**

#### 删除清单

| 文件 | 删除内容 |
|---|---|
| `design/types.ts` | `TableElement.columnFields?`、`TableElement.detailRowIndex?`（注释块一并删） |
| `data/tableRender.ts` | **整个文件删除** —— 它的存在意义只有"展开 + 列映射兜底" |
| `data/useDataBinding.ts` | `setColumnField()` 及其导出；`designContext` 注释改写（不再是"面板预览唯一消费"） |
| `table/model.ts` | `insertCol` / `removeCol` 里的 `columnFields.splice`；`insertRow` / `removeRow` 里的 `detailRowIndex` 行号维护 |
| `setting/element/BindingSection.vue` | 表格分组整块（「明细模板行」下拉、「列映射」逐列下拉、「取数预览」整表预览）；文本元素的「取数预览」；随之失效的 `renderTableRows` / `renderTemplate` / `colLabel` import 与 `PREVIEW_ROW_LIMIT` |
| `designPanel/.../TableElement.vue` / `TextElement.vue` | 注释改写（原文引用"面板整表预览"与「取数预览」） |

**净效果**：`BindingSection.vue` 里表格分支**整块消失**，表格的「数据」分组只剩「数据集」一个下拉。
这与 §11.12（拆掉明细行机制）之后的状态基本一致，只是这次连"取数预览"也没有了。

#### 保留清单（刻意没删，别再顺手清）

| 东西 | 为什么留 |
|---|---|
| `data/context.ts`（含 `buildRowContext` / `buildEmptyContext` / `applyFieldFormat`） | 渲染层与数据层之间那条接缝，导出 / 打印要用。它自成模块，删掉等于把"取数"这一半砍掉 |
| `lib/template.ts` 的 `renderTemplate` | 同上。**当前零调用点**，但它是"把占位符变成值"的唯一实现 |
| `useDataBinding.designContext()` | 同上，是渲染态的入口。注释已改为"当前无消费方，留给预览 / 导出 / 打印" |
| `DataPanel.vue` 的 `appendFieldToCell` | **往单元格拖字段仍然有效** —— 它是"把 `{数据集.字段}` 写进这一格"，与数据扩展无关 |
| `TableElement.allowBreakAcrossPages` | 仍是"只存不消费"的预留声明，**老板尚未表态** |

> ⚠️ 上面三条"零消费方"的代码**不是遗漏**。本项目的"只存不消费 = 死数据 = 删"针对的是
> **面板上会误导用户的声明字段**（调了没反应的下拉 / 输入框），不是内部模块。
> 判定标准：**它会不会让用户以为某件事生效了？** 会 → 删；只是暂时没人调 → 留。

#### 现在表格与数据绑定的关系（一句话）

**表格只通过 `BaseElement.binding.dataSetId` 与数据沾边**：它知道"我这张表用哪个数据集"，
单元格里可以有 `{数据集.字段}` 文本，但**没有任何"取数"行为**——不展开行、不填值、不显示值。

#### 做导出 / 套打时要重建的一整套（与本轮改动无关，是那条路的输入）

按这个顺序补回来，**先有声明、再有渲染**：

1. `detailRowIndex`（哪一行是明细模板行）+ `headerRows`（前 N 行是表头，不展开、跨页重复）；
2. `columnFields`（列 → 字段名，兜底填空白格）；
3. 一个纯函数渲染器（`renderTableRows` 那类），**面板与导出共用同一份**——
   这正是 §11.15 做得对的地方，重建时保留这个形状；
4. 套打行数控制三件套：`detailRowsPerPage` / `padEmptyRows` / `summaryOnLastPageOnly`。

⚠️ **重建时先想清楚"画布要不要看见"**。如果答案还是"看不见，只在预览里看得见"，
那就该重新审视它是否属于设计态 —— 这正是本轮返工的原因。

#### 验证（沿用 §11.5 的方式）

- 残留扫描：`columnFields` / `detailRowIndex` / `tableRender` / `renderTableRows` / `RenderedRow` /
  `setColumnField` 在 `src/` **全部 0 命中**。
- `vite`(5215) + `curl --noproxy '*'`：**11 个相关模块全 200**（含三个渲染元素、两个 store、
  `context.ts`、`DataPanel.vue`、`ElementProperties.vue`、`model.ts`）。
- `npx eslint` 改动范围 **0 problem**；全仓仍是那 1 个既有 error（`views/dashboard/index.vue:250`，
  未触及）+ 19 个既有 warning。

#### 需要老板手点一遍的链路

1. 选中**表格** → 右侧「数据」分组里**只有「数据集」一个下拉**，下方无任何输入框 / 预览区。
2. 从字段树拖一个字段到某个单元格 → 格子里出现 `{数据集.字段}`，**表格行数、列数不变**。
3. 选中**文本元素** → 「数据」分组里只有「数据集」+「插入字段」，**没有取值预览区**。
4. （回归）右键菜单插列 / 删列、插行 / 删行仍然正常 —— 这次从这些函数里删掉了
   `columnFields` / `detailRowIndex` 的维护代码，几何本身没动。
