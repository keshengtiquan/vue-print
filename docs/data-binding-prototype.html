2. 数据集编辑器：SQL 与接口两个页签

两种方式的表单差异只在中间那一段（查询定义），参数、字段解析、预览完全共用 —— 这是"三层模型"带来的直接收益。SQL 侧强调"只选已登记的连接、只允许单条 SELECT"；接口侧多了取值路径。

3. 执行链路（这一条需要拍板）

浏览器不可能也不应该直连数据库，所以 SQL 只能"声明在模板里、执行在宿主侧"。上排是设计态与预览态，下排是打印态。虚线表示数据不经过浏览器。

4. 明细行的展开规则（一期）

三个行角色里只有明细模板行会被复制。这条规则决定了行高是不是权威值，也决定了跨页表头的实现方式，属于一旦做错就要返工的骨架决定。

需要老板确认的 8 条

完整说明见计划书 §9。前三条卡着实现方式，最好先定。

  1. SQL 由谁执行？建议：宿主托管为主，我们附一份 Node 参考实现。
  2. 三个数据接口的契约（test / run / context）是否按草案定。
  3. 一期是否只做单数据集，不做主从关联。
  4. 绑定语法用 {字段} / {数据集.字段} / {$系统变量}。
  5. 打印入参怎么传给模板（宿主 SDK / URL 参数 / postMessage）。
  6. SQL 是否允许 JOIN 与子查询（建议允许，禁多语句）。
  7. 多页渲染器排在哪个阶段（只卡跨页表头与分页，不阻塞绑定）。
  8. 是否需要数据集结果缓存或定时同步（建议一期不做）。
